# DevBar 实现规格

> 本文是给实现者（Codex / Grok）的**施工图**。产品决定以 `菜单栏工具方案.md`（第 9 版，下称「方案」）为准；本文把方案落到工程结构、接口、算法、任务单和验收上。
> 两份文件冲突时：**产品行为以方案为准，工程做法以本文为准**，并在任务回报里指出冲突。
> 审核由 Claude 按 `docs/审核清单.md` 进行。

## 2. 构建与工具链

| 项 | 规定 |
|---|---|
| Swift | 6.x 工具链，`swift-tools-version: 6.2`（`.macOS(.v26)` 需要），`swiftLanguageModes: [.v6]`（严格并发） |
| 最低系统 | `.macOS(.v26)`（需要 `swift-tools-version: 6.2` 及以上）；**只支持 macOS 26，不写任何旧系统分支**（不写 `if #available` 兼容旧版本、不保留旧材质回退） |
| 构建方式 | **SwiftPM + 脚本组装 .app**（不建 .xcodeproj），参考 `Reference/Vorssaint/build.sh` 的做法但大幅简化 |
| Swift 依赖 | 仅 `KeyboardShortcuts`（sindresorhus），写死具体版本 `.exact("x.y.z")` |
| Node | 本机 Node 22+ / npm；`npm ci` 安装 |
| 前端构建 | Vite，产物输出到 `Web/dist/`，由 `build-app.sh` 拷进 `DevBar.app/Contents/Resources/Web/` |
| 格式化 | Swift：`swift format`（工具链自带）；Web：Prettier |
| Lint | Web：ESLint（含 §3.3 的自定义规则，规则本身要有 `RuleTester` 单测）；Swift：`swift format lint --strict`（不加 `--strict` 时违规也返回 0） |
| Vite | `build.modulePreload: false`：默认注入的 modulepreload polyfill 会调用 `fetch`，违反不联网红线 |
| 测试 | Swift：Swift Testing（`swift test`）；Web：Vitest（`npm test`） |

  .testTarget(name: "DevBarCaptureTests", dependencies: ["DevBarCapture"]),

### 2.2 `Scripts/build-app.sh`

用法：`Scripts/build-app.sh [debug|release]`，默认 `debug`。步骤：

1. `cd Web && npm ci && npm run build`（`Web/dist/` 已存在且源码未变时可跳过，用文件时间判断即可）。
2. `swift build -c <配置>`。
3. 组装 `build/DevBar.app`：`Contents/MacOS/DevBar`、`Contents/Info.plist`、`Contents/Resources/Web/`、`Contents/Resources/AppIcon.icns`、`Contents/Resources/Licenses/`（开源许可文本）。
4. 签名：
   - 签名前 `xattr -cr` 清掉扩展属性（项目在「桌面」时，`com.apple.provenance` 会让 `codesign --strict` 失败）。
   - 环境变量 `DEVBAR_SIGN_IDENTITY` 有值时，用它签名（本机自用阶段用固定的 Apple Development 证书，**这样屏幕录制等权限不会每次构建后失效**）。
   - 没有时退回 ad-hoc（`--sign -`），并打印警告「权限可能每次构建后失效」。
   - Release + Developer ID 时加 `--options runtime --timestamp`（第 7 期才需要）。
5. `codesign --verify --deep --strict build/DevBar.app`。
6. 不安装到 /Applications，不自动启动（由人决定）。

### 2.3 `Info.plist` 关键项

| 键 | 值 |
|---|---|
| `CFBundleIdentifier` | `local.devbar.app`（内部使用的占位，第 7 期按公司规范改） |
| `CFBundleName` / `CFBundleDisplayName` | `DevBar` |
| `LSUIElement` | `true`（只在菜单栏，没有 Dock 图标） |
| `LSMinimumSystemVersion` | `26.0` |
| `NSMicrophoneUsageDescription` | 「录屏时录制麦克风声音。」 |
| `NSHumanReadableCopyright` | 含开源许可说明入口 |

屏幕录制没有 Info.plist 键，由系统在首次采集时弹窗。

### 2.4 `Scripts/check.sh`

依次运行，任一失败即退出非零：`swift format lint --strict -r Sources Tests`、`swift build`、`swift test`、`cd Web && npm run lint && npm test && npm run build`（`Web/node_modules` 不存在时先 `npm ci`）、`Scripts/gen-tokens.ts --check`（产物与 `tokens.json` 一致）。**每个任务回报前必须跑一次并附输出末尾。**

## 3. 全局编码规则

### 3.1 通用

- 界面文字全部中文，集中在 `Sources/DevBar/Strings.swift` 和 `Web/src/strings.ts`，不散落在各处。
- 不联网：Swift 侧不出现 `URLSession` 对外请求；Web 侧不出现 `fetch` 到 `http(s)`。
- 不记录用户内容到日志（剪贴板、工具、文稿的内容一律不打日志；只记事件类型和长度）。
- 不使用 Vorssaint 的名字、图标、bundle id、文案；抽取来的文件保留原 GPL 版权头，再加一行 `// Adapted for DevBar.`。

### 3.2 Swift

- 严格并发：UI 相关类型标 `@MainActor`；存储用 `actor`；跨线程只传 `Sendable` 值。
- 状态用 Observation（`@Observable`），不用 `ObservableObject`。
- `DevBarCore` 不得 import AppKit / SwiftUI / WebKit / ScreenCaptureKit，便于不启动界面就能测。
- 不得出现字面颜色值（`Color(red:…)`、`NSColor(calibratedRed:…)`、十六进制），只能用生成的 `DesignTokens`。
- 错误用具体的 `enum … : Error`，不用字符串错误；用户可见的错误文案走 `Strings`。

### 3.3 Web

- TypeScript `strict: true`，不用 `any`（确有必要时加注释说明）。
- **ESLint 自定义规则（必须实现并启用）**：
  1. `src/tools/`、`src/tree/` 下禁止 `JSON.parse(` / `JSON.stringify(`；只能用 lossless-json。`src/bridge/envelope.ts` 例外（只处理消息信封）。
  2. 全部 `src/` 下禁止 `eval`、`new Function`、`setTimeout("字符串")`。
  3. 全部 `src/` 下（`src/theme/` 生成产物除外）禁止字面颜色值：十六进制颜色、`rgb(`、`rgba(`、`hsl(`；CSS 文件里同样检查（用 stylelint 或自写脚本）。
  4. 禁止 `fetch(`、`XMLHttpRequest`、`WebSocket`、`EventSource`。
- 不用框架（React / Vue 等），直接操作 DOM；保持包体小。
- 所有对编辑器内容的修改都通过 CodeMirror 事务完成，带 `userEvent`，保证 ⌘Z 可撤销（§7.2）。

## 4. 设计变量（tokens）

### 4.1 `design/tokens.json` 结构

按**语义角色**定义，白、黑各一套。每个值写成「基色 + 不透明度」，生成器负责换算成各端格式。

```json
{
  "light": {
    "panel.base":      { "color": "#FFFFFF", "alpha": 0.68 },
    "panel.card":      { "color": "#FFFFFF", "alpha": 0.38 },
    "panel.control":   { "color": "#000000", "alpha": 0.055 },
    "panel.raised":    { "color": "#FFFFFF", "alpha": 0.88 },
    "line.border":     { "color": "#000000", "alpha": 0.09, "highContrast": 0.24 },
    "line.divider":    { "color": "#000000", "alpha": 0.12 },
    "text.primary":    { "color": "#000000", "alpha": 1.0 },
    "text.secondary":  { "color": "#000000", "alpha": 0.75 },
    "text.tertiary":   { "color": "#000000", "alpha": 0.60 },
    "syntax.keyword":  { "ref": "text.primary", "weight": 600 },
    "syntax.string":   { "ref": "text.secondary" },
    "syntax.number":   { "ref": "text.primary", "tabular": true },
    "syntax.constant": { "ref": "text.primary", "italic": true },
    "syntax.comment":  { "ref": "text.tertiary", "italic": true },
    "syntax.punct":    { "ref": "text.tertiary" },
    "selection.fill":  { "ref": "text.primary" },
    "selection.text":  { "color": "#FFFFFF", "alpha": 1.0 }
  },
  "dark": { "...": "同结构，数值取方案 §3 与 Vorssaint PanelSurface 的黑主题" },
  "radius": { "small": 7, "medium": 10, "large": 12, "inline": 4 },
  "stroke": { "hairline": 0.7, "strong": 1.0 },
  "font":   { "body": 14, "bodyLarge": 15, "lineHeight": 1.65 },
  "opaqueBackdrop": { "light": "#F2F2F2", "dark": "#1C1C1E" }
}
```

- 数值来源：`Reference/Vorssaint/Sources/Vorssaint/UI/Theme.swift` 的 `PanelSurface`（底、卡片、控件、凸起、描边、高对比描边）。
- **任何文字类角色的 `alpha` 不得低于 0.60**（方案 §3.1），生成器遇到违规直接报错。
- `opaqueBackdrop`：玻璃底下「假定的背景色」，用于把半透明色换算成不透明十六进制（Mermaid、PNG 导出需要）。

### 4.2 生成产物（`Scripts/gen-tokens.ts`，Node 运行）

| 产物 | 路径 | 格式 |
|---|---|---|
| Swift | `Sources/DevBar/Generated/DesignTokens.swift` | `enum DesignTokens { static func panelBase(_ scheme: ColorScheme) -> Color … }`；高对比描边读 `NSWorkspace.shared.accessibilityDisplayShouldIncreaseContrast` |
| CSS | `Web/src/theme/tokens.css` | `:root[data-theme="light"] { --text-primary: rgba(…); … }`，黑同理 |
| CodeMirror | `Web/src/theme/cm-highlight.ts` | `HighlightStyle.define([...])`，颜色引用 CSS 变量 |
| Shiki | `Web/src/theme/shiki-devbar-light.json` / `-dark.json` | Shiki 主题 JSON；颜色写成换算后的十六进制（带 alpha 的 8 位十六进制可以） |
| Mermaid | `Web/src/theme/mermaid-vars.ts` | `export const mermaidVars = { light: {...}, dark: {...} }`，**全部为不透明 6 位十六进制**（按 `opaqueBackdrop` 叠色换算） |

- 产物文件头写「自动生成，勿手改」。
- `gen-tokens.ts --check`：重新生成到临时目录并与仓库内产物比较，不一致即失败。

### 4.3 主题切换

- 原生 `ThemeManager`（`@Observable`）：`mode: .system | .light | .dark`，存 `UserDefaults`；`effective: .light | .dark` 由 `mode` 和系统外观（`NSApp.effectiveAppearance`）计算，监听系统外观变化。
- `effective` 变化时：原生界面刷新；向 Web 发 `theme.set`（§5.3）；Web 设置 `<html data-theme>`，Shiki 重新着色可见代码块，Mermaid 用缓存源码重新渲染。

## 5. 原生 ↔ Web 桥接

### 5.1 通道

- **Web → 原生**：`window.webkit.messageHandlers.devbar.postMessage(envelope)`，原生用 `WKScriptMessageHandlerWithReply` 回复，Web 侧得到 `Promise`。
- **原生 → Web**：`webView.callAsyncJavaScript("return await window.__devbar.receive(env)", arguments: ["env": envelopeString], in: nil, contentWorld: .page)`。
- 信封统一为 JSON 字符串：`{"v":1,"id":"<uuid>","type":"<类型>","payload":{...}}`。
- **用户内容（JSON 正文、文稿、剪贴板文本）在 payload 里只作为字符串字段出现**。Swift 端用 `Codable` 解析信封，但用户内容字段类型一律是 `String`，从不进一步解析（方案 §5.2）。
- 两端各维护一份类型定义：`Sources/DevBar/Web/BridgeMessages.swift`、`Web/src/bridge/messages.ts`。**契约测试**：`Tests/` 与 `Web/tests/` 各有一组固定的信封样例文件（`Samples/bridge/*.json`），两端都要能解码 / 编码得到相同结果。

### 5.2 Web → 原生

| type | payload | 回复 | 说明 |
|---|---|---|---|
| `app.ready` | `{ version }` | `{ theme, mode, panelSize, settings }` | Web 加载完成；原生回初始状态 |
| `clipboard.readText` | `{}` | `{ status: "ok", text } \| { status: "denied" \| "ask" \| "empty" \| "concealed" \| "notText" }` | 读取前按方案 §4.4 检查授权；带隐私标记返回 `concealed` |
| `clipboard.writeText` | `{ text }` | `{ ok: true }` | 写入系统剪贴板（会正常进入历史） |
| `clipboard.writeImage` | `{ pngBase64 }` | `{ ok: true }` | Mermaid 复制为 PNG |
| `qr.show` | `{ text }` | `{ status: "shown" } \| { status: "tooLarge", bytes, limit: 2331 }` | 原生生成并弹出二维码小面板 |
| `state.save` | `{ screen: "tools" \| "doc", state }` | `{ ok: true }` | 停止输入 1 秒后调用；`state` 见 §7.8 / §8.7 |
| `state.load` | `{ screen }` | `{ state \| null }` | 启动和 WebView 重建后调用 |
| `link.open` | `{ url }` | `{ opened: boolean }` | 仅 `http` / `https`，由原生交给系统浏览器（§8.6） |
| `ui.toast` | `{ text }` | `{}` | 让原生在面板底部显示一行轻提示（可选，Web 也可自己显示） |

### 5.3 原生 → Web

| type | payload | 说明 |
|---|---|---|
| `theme.set` | `{ theme: "light" \| "dark" }` | |
| `screen.show` | `{ screen: "tools" \| "doc" }` | 切换显示的屏；两个屏的 DOM 都常驻，只切显隐，保证撤销历史不丢 |
| `panel.size` | `{ size: "normal" \| "large" }` | 正文字号 14 / 15 |
| `tools.import` | `{ text, mode: "ifEmpty" \| "replace", fileName?: string }` | `ifEmpty`：编辑区为空才带入；`replace`：⌥⌘J 或文件拖入，明确替换，作为一次可撤销事务；有 `fileName` 时显示文件名提示（§6.7） |
| `doc.import` | `{ text, fileName?: string, docMode?: "markdown" \| "mermaid" }` | 【第 10 版】文件拖入文稿：一次可撤销事务替换全文；`docMode` 由扩展名决定时传入并锁定，否则由 Web 按 §8.11.1 判断 |
| `memory.flush` | `{}` | 内存紧张前，Web 立即执行一次 `state.save` 并回复 |
| `settings.set` | `{ autoImport: boolean }` | 设置变化 |

### 5.4 WebView 宿主（`Sources/DevBar/Web/`）

- `WebHost`（`@MainActor`）持有**唯一一个** `WKWebView`，应用启动后创建并加载 `devbar://app/index.html`，收到 `app.ready` 前的原生消息排队。
- `WKWebViewConfiguration`：
  - `setURLSchemeHandler(DevBarSchemeHandler(), forURLScheme: "devbar")`。
  - `websiteDataStore = .nonPersistent()`（不依赖 localStorage，状态走 `state.save`）。
  - `preferences.javaScriptCanOpenWindowsAutomatically = false`。
  - Debug 构建 `webView.isInspectable = true`，Release 为 `false`。
- `DevBarSchemeHandler`：只从 `Bundle.main.resourceURL/Web/` 读文件；拒绝 `..` 路径；按扩展名给 MIME：`html → text/html`、`js/mjs → text/javascript`、`css → text/css`、`json → application/json`、`svg → image/svg+xml`、`png → image/png`、`woff2 → font/woff2`；**每个响应都带 CSP 响应头**：

```
Content-Security-Policy: default-src devbar:; script-src devbar:; style-src devbar: 'unsafe-inline'; img-src devbar: data: blob:; font-src devbar: data:; worker-src devbar: blob:; connect-src devbar:; object-src 'none'; base-uri 'none'; form-action 'none'
```

  `index.html` 里再放一份同内容的 `<meta http-equiv>`，双保险。不得出现 `unsafe-eval`、`wasm-unsafe-eval`。
- `WKContentRuleList`：一条规则 `{"trigger":{"url-filter":"^https?://"},"action":{"type":"block"}}`，编译后加入 `userContentController`。
- `WKNavigationDelegate.decidePolicyFor`：只允许 `devbar://app/` 下的主框架加载，其他一律 `.cancel`（链接点击走 `link.open`）。
- 进程崩溃（`webViewWebContentProcessDidTerminate`）：重建 WebView，重新加载，Web 启动后 `state.load` 恢复内容。
- 内存压力：`DispatchSource.makeMemoryPressureSource(eventMask: .critical)`；触发时若面板未显示，先发 `memory.flush` 等回复（最多 1 秒），再释放 WebView；下次打开面板时重建。撤销历史因此丢失（方案允许）。

## 6. 原生应用骨架（`Sources/DevBar/App/`）

> **【方案第 11 版，2026-11-10】以下几处以本框为准，与下文冲突的描述作废：**
> - 面板里**没有页签栏、没有侧边栏**，一次只显示一页：剪贴板 / 工具 / 文稿。截图录屏**不再是面板里的一页**。外观见 `docs/UI基准.md` §3。
> - 切页：**⌘P** 下一页、**⇧⌘P** 上一页（循环），点顶栏的页面名字也切下一页；在 `DevBarPanel.performKeyEquivalent` 里先处理，保证 WebView 有焦点时也生效（WebView 里的 ⌘P 打印被拦截）。**删除 ⌘1–⌘4**。
> - 面板记住上次停留的页（`UserDefaults`）；⌥⌘J、文件拖入直接切到对应页。
> - 右键菜单栏图标：「区域截图」「长图」「开始录屏 / 停止录屏」「设置…」「关于与开源许可」「退出 DevBar」。
> - 设置页新增「录屏：系统声音」「录屏：麦克风」两个开关（默认关）。

  - 松在覆盖层左 / 右 → 按所在区域打开；
  - 松在菜单栏图标上 → 按预选去向打开；

**路由**（`DevBarCore/FileDrop/FileRoute.swift`，纯逻辑，可单测）

```swift
public enum FileRoute: Equatable, Sendable { case tools, doc(DocMode?), rejected(Reason) }
public enum DocMode: String, Sendable { case markdown, mermaid }
public static func route(fileName: String, sniff: String?) -> FileRoute
```

| 扩展名（不区分大小写） | 结果 |
|---|---|
| `json` `jsonc` `geojson` | `.tools` |
| `md` `markdown` | `.doc(.markdown)` |
| `mmd` `mermaid` | `.doc(.mermaid)` |
| `txt` 或无扩展名 | `sniff`（文件前 4KB 解码后的文本）去掉前导空白后以 `{` / `[` 开头 → `.tools`；否则 `.doc(nil)`（由 Web 判断模式） |
| 其他 | `.rejected(.unsupportedType)` |

**读取**（`FileDropReader`）

1. 只取第一个文件；多于一个时轻提示「已打开第一个文件」。
2. 不是普通文件（目录、包）→ 拒绝。
3. 大小 > 10MB（`URLResourceValues.fileSize`）→ 拒绝，提示「文件超过 10MB，未打开」，不读取内容。
4. 读取 `Data`；去掉 UTF-8 BOM；用 `String(data:encoding:.utf8)` 严格解码，失败 → 提示「只支持 UTF-8 文本文件」。
5. 按路由发 `tools.import { text, mode: "replace", fileName }` 或 `doc.import { text, fileName, docMode }`，并切到对应页。
6. 拒绝时的提示都走面板底部轻提示，不弹窗；文件内容不写日志（只记扩展名和字节数）。

**Web 侧的文件名提示**

- 编辑区顶部一行次要文字：「文件名 · 只读，不会保存回文件」。
- 内容被清空、或被下一次导入（剪贴板带入、⌥⌘J、再次拖入）替换时，提示消失 / 更新；用户修改内容时保持。
- 文件名随 `state.save` 一起保存，重启后恢复。

## 7. 剪贴板（方案 §4）

### 7.1 数据模型（`DevBarCore/Clipboard/`）

```swift
public struct ClipItem: Codable, Sendable, Identifiable, Equatable {
  public let id: UUID
  public var kind: Kind                     // .text / .image / .files
  public var createdAt: Date
  public var sourceBundleID: String?        // 复制时的前台应用
  public var preview: String                // 文本前两行（≤ 200 字符）；图片为尺寸描述；文件为文件名
  public var representations: [Representation]  // 写回剪贴板用的全部表示
  public var contentHash: String            // SHA-256，判重用
  public var byteSize: Int
  public enum Kind: String, Codable, Sendable { case text, image, files }
}

public struct Representation: Codable, Sendable, Equatable {
  public var type: String      // UTI，例如 public.utf8-plain-text / public.rtf / public.html / public.png / public.tiff / public.file-url
  public var blob: String      // blobs/ 下的文件名
}
```

- **保真**：文本条目同时保存 `public.utf8-plain-text`，以及存在时的 `public.rtf`、`public.html`；图片保存原始类型的数据（png / tiff / jpeg / heic 原样）；文件保存每个 `public.file-url`。写回时按原类型全部写回，**不用缩略图代替原图**。
- 缩略图单独存 `thumbs/<id>.png`（最长边 160px @2x），只用于列表显示。

### 7.2 存储（`ClipboardStore`，`actor`）

- 目录：`~/Library/Application Support/DevBar/clipboard/`，内含 `index.json`、`blobs/`、`thumbs/`。
- `index.json`：`{ "version": 1, "items": [ClipItem] }`，最新在前。
- **原子写入**：写到 `index.json.tmp` 再 `FileManager.replaceItemAt`。
- 上限：**10 条**；第 11 条进入时删除最旧条目的索引和它的 blobs / thumbs。
- **图片上限 20MB**（所有图片表示合计）：超过则不入历史，通过回调让界面轻提示一次「图片太大，未记录」，**不改动系统剪贴板**。
- 启动时：读取索引；删除索引引用但文件缺失的条目；删除 `blobs/`、`thumbs/` 里没有被索引引用的文件。
- 【R3 审核补充】索引损坏（无法解析）且没有可用的 `index.json.tmp` 时：把坏文件改名为 `index.json.corrupt-<yyyyMMdd-HHmmss>` 保留现场，从空历史开始，回调通知界面轻提示一次「剪贴板历史已损坏，已重新开始」。不得因此让存储初始化失败。
- 判重：新条目 `contentHash` 与已有条目相同 → 不新增，把已有条目移到最前并更新 `createdAt`。

### 7.3 监听（`ClipboardMonitor`，`@MainActor`）

- 每 0.5 秒读一次 `NSPasteboard.general.changeCount`（只读计数，不读内容）。
- 变化时：
  1. 若等于 `lastSelfWrite`（本应用自己写入后记录的计数）→ 忽略。
  2. 检查读取授权（§7.4），不是「允许」→ 按 §7.4 处理，不读内容。
  3. 若剪贴板类型里有 `org.nspasteboard.ConcealedType`、`org.nspasteboard.TransientType`、`org.nspasteboard.AutoGeneratedType` → 忽略（参考 `Reference/Vorssaint/Sources/Vorssaint/Services/Clipboard/ClipboardHistorySupport.swift` 第 1115–1130 行附近）。
  4. 读取表示 → 交给 `ClipboardStore.add`。
  5. 「当前」指针回到第 1 条（§7.5）。
- `sourceBundleID`：取 `NSWorkspace.shared.frontmostApplication?.bundleIdentifier`。

### 7.4 读取授权

- **实现前先查 SDK 头文件**：确认 `NSPasteboard.accessBehavior`（及相关枚举）的可用系统版本和枚举值，用 `if #available` 包裹；不可用的系统按「允许」处理。把查到的版本号和枚举写进 `docs/验证记录/剪贴板授权.md`。
- 状态处理按方案 §4.4。授权状态和「有新内容待记录」作为 `ClipboardMonitor` 的可观察属性，剪贴板页据此显示说明条和按钮。
- ~~能不读内容就判断类型时，优先用 `NSPasteboard` 的 detect 系列接口~~（V3 结论：不接入，见下）。

**【V3 实测结论，2026-11-10；已按 Codex 复核意见修正，详见 `docs/验证记录/剪贴板授权.md`】**

- 接口：`NSPasteboard.accessBehavior`（`.default` / `.ask` / `.alwaysAllow` / `.alwaysDeny`），macOS 15.4 起即有；最低系统已是 26，**直接调用，不写版本判断**。
- 观察范围：**本机（macOS 26.7.2）、探针的应用身份与配置下**读到 `.alwaysAllow`、不弹窗。这**不能推广**到所有应用和所有系统配置。
- 验收方式：各授权分支用注入假 `PasteboardReading` 的单元测试覆盖；**真实系统下的询问 / 拒绝行为列为条件性验收**——系统对 DevBar 启用这项保护时补测，目前记为「未验证」，单元测试不能替代它。
- 实现要求：
  1. **`.default` 按「询问」处理**：后台不读内容（头文件：第一次程序化读取会触发系统提示）。
  2. **读内容可能同步阻塞到用户点完系统弹窗**（实测 2.6–15.3 秒）。后台监听在非「允许」状态下绝不读内容；用户主动触发的读取（剪贴板页「有新内容，点击记录」、⌥⌘J、工具页自动带入）放到**真正的后台执行上下文**（例如 `nonisolated` 的异步函数或 `Task.detached`，不能用会继承主线程隔离的普通 `Task {}`），界面显示「等待系统授权…」。
  3. **返回 `nil` 不等于被拒绝**：剪贴板为空、不含字符串时也会返回 `nil`。只提示「未读取到文本」；只有授权状态（`.alwaysDeny`）或明确的错误能证明被拒绝时，才提示「未获准读取剪贴板」。不自动重试；弹窗的「不允许」只管一次，不记成永久拒绝。
  4. **读类型列表、`changeCount`、`accessBehavior` 不会触发提示**：§7.3 第 3 步的隐私类型过滤（`ConcealedType` 等）放在授权判断**之前**。过滤后再读内容时，读完要再比对一次 `changeCount`，变了就丢弃这次结果（防止类型检查和读取之间剪贴板已经换了内容）。
  5. **检测接口不接入**。三个接口的隐私行为不同（以头文件为准）：`detectedPatterns` 只返回是否匹配、不取内容；`detectedMetadata` 只取有限元数据、不通知用户；**`detectedValues` 匹配时会读取内容并通知用户，用户拒绝时返回错误**。V3 探针只调用了前两个。
- **不在 DevBar 里打开** `EnablePasteboardPrivacyDeveloperPreview`。

### 7.5 切换（`ClipboardCycler`）

- 状态：`currentIndex: Int`（0 = 最新）。
- `cycleOlder`：`currentIndex < count - 1` 时 +1，否则 HUD 抖动；`cycleNewer`：`> 0` 时 −1，否则抖动。
- 每次切换：把 `items[currentIndex]` 的全部表示写入 `NSPasteboard.general`（`clearContents` 后 `writeObjects` / `setData`），记录写入后的 `changeCount` 为 `lastSelfWrite`；**不改变列表顺序**。
- 有新复制进入历史时 `currentIndex = 0`。
- 列表点击 / 回车「设为当前」：同样走写入流程，并把 `currentIndex` 设为该行。

### 7.7 列表界面

- 每行高 56：左侧来源应用图标 16pt；中间预览（最多两行，代码类文本用等宽字体，判定规则：含 `{`、`;`、`=>`、`</` 等且行数 ≥ 2 时用等宽）；右侧相对时间（「刚刚」「3 分钟前」「昨天」）。

### 8.1 页面骨架

- `index.html` 内两个屏：`<section id="tools">`、`<section id="doc">`，同时常驻，`screen.show` 切换 `hidden`。
- 每个屏顶部一条工具栏，下方内容区；内容区内「原文」（CodeMirror）和「预览」两层，⌘E 切换显隐（**不销毁原文编辑器**）。

### 8.2 CodeMirror 公共配置（`src/editor/`）

- 扩展：`history()`、`drawSelection()`、`highlightSpecialChars()`、`EditorView.lineWrapping`（工具和文稿都换行）、`keymap.of([...defaultKeymap, ...historyKeymap, ...searchKeymap])`、`syntaxHighlighting(devbarHighlight)`（来自生成的 `cm-highlight.ts`）。
- 不开行号、不开折叠、不开自动补全、不开括号自动闭合（避免粘贴后改动内容）。

- 封装 `replaceAll(view, text, userEvent)`：一次事务替换全文，`userEvent` 取 `"devbar.import"` / `"devbar.transform"` / `"devbar.repair"`，进入撤销历史。

### 8.3 类型识别（`src/tools/detect.ts`）

签名：`detect(text: string): Detection`，`Detection = { type: "json" | "url" | "base64" | "text", json?: "valid" | "repairable" | "invalid", hint?: "escapedJson" }`。

按顺序判断，命中即返回；**拿不准就是 `text`**：

1. `t = text.trim()`；为空 → `text`。
2. **JSON**：`t` 以 `{` 或 `[` 开头 → 用 lossless-json `parse` 成功则 `valid`；否则 `jsonrepair(t)` 成功且结果能 `parse` 则 `repairable`；否则**再看结构**（【R2 审核补充】）：`{` 后第一个非空白字符是 `"`、`'`、`}`，或第一行含 `:`；`[` 后第一个非空白字符是 `{`、`[`、`]`、`"`、`'`、`-`、数字、`t`/`f`/`n`（`true`/`false`/`null` 开头）——满足才判为 `invalid`（以便标出错误位置），否则判为 `text`。例：`[TODO] fix bug`、`[ERROR] connection refused`、`{name}` → `text`。
3. **转义过的 JSON 提示**：`t` 以 `"` 开头和结尾，按 JSON 字符串字面量解析成功，且解析结果 `trim()` 后以 `{`/`[` 开头并能 `parse` → 返回 `text` 并带 `hint: "escapedJson"`（界面提示「看起来是转义过的 JSON，反转义？」）。
4. **URL**：`t` 不含空白，且匹配 `^[A-Za-z][A-Za-z0-9+.-]*://[^\s]+$` → `url`。
5. ~~时间戳~~（第 12 版删除，纯数字一律当普通文本；后面的序号照常顺延即可）。
6. **Base64**：去掉内部空白后长度 ≥ 8；只含 `A-Za-z0-9+/=` 或只含 `A-Za-z0-9-_=`（不能混用两套）；补齐 `=` 后长度为 4 的倍数；解码成功；用 `new TextDecoder("utf-8", { fatal: true })` 解成文本成功；文本里除 `\t\n\r` 外没有 C0 控制字符，也没有 C1 控制字符（U+0080–U+009F）；**并且**（【R2 审核补充】）输入不能是「全小写字母」或「首字母大写、其余小写」的纯字母串（这类几乎都是英文单词，解出的是多种文字混杂的乱码）→ `base64`。回归测试：用 macOS 自带 `/usr/share/dict/words` 中长度 ≥ 8 的单词逐个识别，识别成 `base64` 的不超过 10 个（文件不存在时跳过该测试）。
7. 其他 → `text`。

**类型锁定**：用户在左上角手动选了类型后，`lockedType` 生效，`detect` 不再改变显示类型；编辑区被清空时解除锁定。

**重新识别的时机**：导入（`devbar.import`）、粘贴、每次转换之后、输入停止 400ms 后。识别结果只影响「显示哪些按钮」和「预览怎么画」，**从不改动内容**。

### 8.4 复制规则（`src/tools/copy.ts`）

维护 `lastResult: string | null`：

| 类型 | ⌘⇧C / 「复制」按钮复制的内容 | 二维码用的文本 |
|---|---|---|
| JSON | 编辑区当前全文 | 同左 |
| URL、Base64 | `lastResult ?? 编辑区当前全文`；`lastResult` 在每次编码 / 解码后更新为结果，用户手动编辑后清空 | 同左 |
| 普通文本 | 编辑区当前全文 | 同左 |

> URL / Base64 的编码解码结果**同时写回编辑区**（可撤销事务），`lastResult` 等于写回后的全文。这样「看到的就是会复制的」。

复制走 `clipboard.writeText`。

### 8.5 JSON（`src/tools/json/`）

依赖：`lossless-json`、`jsonrepair`。

- **自动格式化**：仅在「导入」或「粘贴后编辑区内容就是这次粘贴的全部内容」时触发；且 `detect` 为 `valid`。格式化 = `stringify(parse(t), null, 2)`，以 `devbar.transform` 事务写回。**用户打字过程中不自动格式化**。
- **格式化 / 压缩按钮**：`valid` 时可用；`space = 2` / 无空白。
- **不合法**：
  - 计算错误位置：从 lossless-json 抛出的错误里取字符位置（不同版本消息格式可能不同，写一个 `positionFromError` 适配并用测试覆盖），换算成「第 X 行第 Y 列」；在该位置加波浪下划线装饰（CodeMirror `Decoration.mark`），状态栏显示「第 X 行第 Y 列：原因」。
  - `repairable` 时状态栏显示「可修复」按钮；点击后 `jsonrepair` → `parse` → `stringify(…, 2)`，以 `devbar.repair` 事务写回。**不显示修复了几处**。
- **转义**：`escapeJsonString(text)`，自己实现：输出以 `"` 包围；转义 `"`、`\`；`\b \f \n \r \t` 用短形式；其他 U+0000–U+001F 用 `\u00XX`（小写十六进制）；**非 ASCII 字符原样保留**。
- **反转义**：`unescapeJsonString(text)`：`t` 以 `"` 开头结尾时直接按字符串字面量解析；否则先在两端补 `"` 再解析（常见情况：粘进来的是 `{\"a\":1}`）。解析器自己实现（处理全部 JSON 转义，包括代理对 `😀`）；失败时提示错误位置，不改内容。
- **大文件**：文本 > 1MB 时，parse / stringify / repair 放进 Web Worker（`src/tools/json/worker.ts`）；超过 300ms 显示进度条和「取消」，取消即 `worker.terminate()` 并保持原内容不变。
- **已知限制**：纯数字键会被 JS 对象排到前面（方案 §5.2），在测试里写一条用例固定这个行为，避免以后被误当成 bug 修。

### 8.6 JSON 只读树（`src/tree/`）

- 输入：lossless-json `parse` 的结果（数字为 `LosslessNumber`）。
- 渲染：每行 = 缩进 + 展开箭头（容器才有）+ 键 + 值摘要。值摘要：字符串加引号、超过 80 字符省略；数字显示原始写法（`LosslessNumber.value`）；容器显示 `{…} 3 项` / `[…] 120 项`。
- 默认展开两层（根和根的直接子项）。
- **按需创建**：节点首次展开时才创建其子行 DOM；子项超过 200 个时先创建前 200 个，末尾一行「再显示 200 个（剩余 N）」。
- **动作分离**：箭头（以及整行左侧 16pt 热区）只负责展开 / 折叠；悬停行时右侧出现「复制值」「复制路径」两个小按钮；单击行其他区域无动作。
- 复制值：字符串复制**不带引号**的原值；数字复制原始写法；`true/false/null` 复制字面量；容器复制 `stringify(node, null, 2)`。
- 复制路径：根为 `$`；键为合法标识符时 `.key`，否则 `["key"]`（键内 `"` 和 `\` 转义）；数组下标 `[3]`。例：`$.data.items[3]["user name"]`。
- 样式按 tokens：键 `syntax.keyword`、字符串 `syntax.string`、数字 `syntax.number`、`true/false/null` `syntax.constant`、标点 `syntax.punct`、缩进引导线 0.7pt `line.divider`。

### 8.7 URL（`src/tools/url/`）

- **组件编码** `encodeComponent(s)`：UTF-8 编码后，除 `A-Z a-z 0-9 - . _ ~` 外每个字节编码为 `%XX`（大写十六进制）。
- **整段编码** `encodeWhole(s)`：保留 unreserved、reserved（`:/?#[]@!$&'()*+,;=`），以及**已经合法的 `%XX` 序列**（不二次编码）；其余（空格、中文、`"<>\^\`{|}` 等）按字节编码。
- **解码** `decode(s)`：扫描 `%XX`，合法的连续字节按 UTF-8 解码；**坏的 `%` 序列**（`%G1`、结尾 `%2`）和**解不出合法 UTF-8 的字节**保留原文，并返回它们的区间，编辑区用波浪下划线标出；`+` 在通用解码里**不**转空格。【R2 审核补充】错误要精确到字节：一串连续的 `%XX` 里只有部分字节不合法时，只保留不合法的那几个 `%XX`，其余照常解码（例：`%FF%41` → `%FFA`，错误区间只覆盖 `%FF`）。
- **预览**：自己写分解器，不用 `new URL()`（它会规范化主机、路径，改变用户看到的内容）。分出：协议、用户信息、主机、端口、路径、查询、片段。查询按 `&` 切分、每段按第一个 `=` 切成键值，保留顺序和重复键；表格显示「键 / 值（解码后，`+` 视为空格）」两列，每行一个复制按钮（复制解码后的值）。
- 编码按钮：默认组件编码，下拉切换「整段编码」，选择记住。

### 8.8 Base64（`src/tools/base64.ts`；【第 12 版】时间戳已删除，`timestamp.ts` 与其测试、`detect.ts` 里的时间戳分支一并删掉）

- **Base64 编码**：文本 → UTF-8 → 标准字母表、带 `=` 补齐。
- **Base64 解码**：接受标准和 URL 安全字母表、有无补齐、中间有换行空格；解出的字节用 `fatal` UTF-8 解码，失败则状态栏提示「解码结果是二进制内容（N 字节），无法以文本显示」，**不改内容**。【R2 审核补充】解码成功但含 `\t\n\r` 以外的 C0 控制字符（如 `AAECAwQFBgc=` 解出 `\u0000…\u0007`）同样按二进制处理，不把控制字符写进编辑区。

### 8.9 二维码

Web 只发 `qr.show { text }`。原生：

- UTF-8 字节数 > 2331 → 回复 `tooLarge`，Web 在按钮旁提示「内容 N 字节，超过二维码容量 2331 字节」，**不截断**。
- 否则 `CIFilter.qrCodeGenerator()`，`correctionLevel = "M"`，用 `CGAffineTransform(scaleX:y:)` 放大到约 560px，`interpolationQuality = .none`（最近邻）；黑码白底，四周留 4 模块静区。
- 小面板（挂在主面板上的浮层）：二维码图 + 「复制 PNG」+「存储为 PNG…」（`NSSavePanel`）；Esc 关闭。

### 8.11 文稿（`src/doc/`）

**原文**：§8.2 公共配置 + `@codemirror/lang-markdown`（代码块内嵌语言高亮：用 `codeLanguages` 接入 `@codemirror/language-data` 中**与 §8.12 相同的语言子集**，不全量引入）。

**预览管线**（切到预览时执行；内容未变则复用上次结果）：

1. markdown-it：`{ html: true, linkify: false, typographer: false, breaks: false }`；插件：`markdown-it-task-lists`（或同等 MIT 插件，锁版本）。表格用内置 GFM 表格。
2. 自定义 `fence` 渲染：
   - 语言为 `mermaid` → 输出 `<div class="mmd" data-src="…(源码，HTML 转义)" data-idx="n"></div>` 占位。
   - 其他 → Shiki 高亮（§8.12）；语言不在列表或高亮失败 → `<pre class="code plain"><code>…转义后的原文…</code></pre>`。
3. 表格后处理：给每个 `<table>` 包一层 `<div class="table-wrap">`；对**没有显式对齐**的列，若该列所有非空单元格匹配 `^[+-]?(\d{1,3}(,\d{3})+|\d+)(\.\d+)?%?$` → 给该列单元格加 class `num`（右对齐 + `tabular-nums`）。**不改单元格文本**。
4. DOMPurify 清理 markdown-it 输出的 HTML（允许 `class`、`data-src`、`data-idx`、`data-line`；禁止 `style` 属性以外的内联事件与 `script`；`img` 的 `src` 只允许 `devbar:` / `data:`，其余替换为占位）。
5. 插入 DOM，然后逐个渲染 Mermaid 占位（§8.13）。

**链接**：预览中普通点击不跳转；⌘ + 点击 → `link.open`（仅 http / https）。

**外链图片**：显示占位框「外部图片未加载」+ 地址（次要文字）。不提供「加载此图片」（方案已删联网）。

**持久化**：`{ text, view, selection, scrollTop, docMode, modeLocked, fileName }`，写到 `state/doc.json`，规则同 §8.10。只此一份。

#### 8.11.1 【第 10 版】纯 Mermaid 模式（方案 §6.1）

- 状态：`docMode: "markdown" | "mermaid"`，`modeLocked: boolean`。
- **判断** `detectDocMode(text): "markdown" | "mermaid"`（`src/doc/mode.ts`，纯函数）：
  1. 文本里出现代码围栏（行首 ```` ``` ```` 或 `~~~`）→ `markdown`。
  2. 跳过开头的空行、以 `%%` 开头的行、以及首行为 `---` 的 frontmatter 块（到下一个 `---` 为止）。
  3. 第一条有效行（去掉前导空白）以图类型关键字开头，且关键字后是行尾、空白、`-`（如 `stateDiagram-v2`）或 `:` → `mermaid`；否则 `markdown`。
  3a. 【R6 审核补充，堵误判】只满足第 3 条还不够，普通英文句子会被误判（如 `timeline of the project…`、`pie charts are…`、`journey to…`、`block …`、`graph is…`）。再加两条，任一不满足就判 `markdown`：
     - 关键字行除关键字外，只允许该图种的头部参数：方向（`TB` `TD` `BT` `RL` `LR`）、`-v2` / `-beta` 之类的后缀、`:` 后的标题，或 `title …`、`showData`、`accTitle`、`accDescr` 等 Mermaid 头部写法；出现两个以上普通单词组成的句子 → 不算关键字行。
     - 第二条有效行（跳过空行和 `%%`）不能是 Markdown 写法：不以 `#`、`>`、`- `、`* `、`1. `、`|` 开头，也不是普通句子（以句号、问号、中文句号结尾的长句）。只有关键字行、没有第二行时按 `mermaid`。
     宁可漏判成 `markdown`（用户可手动切换并锁定），不要把正文误判成图（方案「不猜改内容」）。
  4. 关键字列表放在 `src/doc/mermaid-keywords.ts`，与锁定版本的 Mermaid 支持的图类型核对一致（T4.7 回报中附核对方法）。
- **时机**：导入、粘贴、输入停止 400ms 后重新判断；`modeLocked` 为真时不判断。
- **锁定**：`doc.import` 带 `docMode`（来自扩展名）时直接采用并锁定；用户在顶部手动切换「Markdown / Mermaid」时锁定；编辑区被清空时解除锁定。
- **预览**：
  - `markdown`：§8.11 原管线。
  - `mermaid`：跳过 markdown-it，整篇文本作为一张图交给 §8.13 的渲染流程（同样的 `stripThemeConfig`、`secure`、SVG 尺寸处理、错误卡片、复制为 PNG）；图在预览区居中、按 SVG 实际尺寸显示，超宽时横向滚动。
- **原文编辑器**：`mermaid` 模式下不挂 Markdown 语言扩展，只显示等宽文本；不改动内容。
- 测试：关键字每种至少一个正例；含代码围栏、普通标题、以 `graph` 开头的普通英文句子（如 `graphs are useful`）、前置 frontmatter 和 `%%` 注释等反例；锁定与解除锁定。
  【R6 审核补充】反例再加：`timeline of the project`、`pie charts are great.`、`journey to the west`、`block quotes`、`graph is useful`，以及关键字行后紧跟 `# 标题` 或 `- 列表` 的文稿。

### 8.13 Mermaid（`src/doc/mermaid.ts`）

- 版本：`package.json` 写死具体 12.x 版本（开工时取最新补丁版并锁定）。
- **动态加载**：文稿里第一次出现 mermaid 占位时 `await import("mermaid")`；之后复用。
- 初始化（每次主题变化时重新调用）：

```ts
mermaid.initialize({
  startOnLoad: false,
  securityLevel: "strict",
  theme: "base",
  themeVariables: { ...mermaidVars[theme], fontFamily: SYSTEM_FONT },
  look: "neo",                    // 不支持 neo 的图种由 Mermaid 自行回退为 classic；验证见 V2
  htmlLabels: false,              // 纯 SVG 文本：PNG 导出不会因 foreignObject 污染画布
  flowchart: { htmlLabels: false, layout: LAYOUT.flowchart },
  state: { layout: LAYOUT.state },
  suppressErrorRendering: true,   // 错误由我们自己显示
  secure: [ ...DEFAULT_SECURE, "theme", "themeVariables", "themeCSS", "look", "fontFamily", "darkMode", "htmlLabels" ],
});
```

  - **【R6 审核定案】流程图、状态图都用 Dagre**，`LAYOUT` 写死为 `"dagre"`，不装 ELK 布局包（`@mermaid-js/layout-elk` 带入的 elkjs 是 EPL-2.0 / GPL-3.0 双许可、按需块约 2MB，对照截图看不出 ELK 的明显优势）。
  - R6 实测：Mermaid 12.3.0 的 `secure` 能挡住 frontmatter 和 `%%{init}%%` 的主题覆盖，**不需要** `stripThemeConfig`；下一条保留作历史。
  - 若 V2 验证发现 `secure` 挡不住 frontmatter：渲染前用 `stripThemeConfig(src)` 去掉 frontmatter 里的 `theme`、`themeVariables`、`themeCSS`、`look`、`fontFamily`、`darkMode`、`htmlLabels` 键，以及 `%%{init…}%%` 中的同名键（**只删这些键，不动其他内容**）。
- 渲染：按顺序逐个 `await mermaid.render("mmd-" + idx + "-" + nonce, src)`；先 `mermaid.parse(src)`，失败则在占位处显示错误卡片：警告图标 + 「Mermaid 语法错误」+ 错误信息 + 行号（取自错误对象），其他图继续渲染。
- 渲染后处理：去掉 `<svg>` 上的 `style="max-width…"` 和 `width="100%"`，按 `viewBox` 设置 `width` / `height` 为实际像素；外层 `.mmd` 卡片 `overflow-x: auto`。
- 缓存：`Map<src + theme, svgString>`，主题切换后按新主题重新渲染。
- **复制为 PNG**：SVG 序列化 → `Image`（`data:image/svg+xml`）→ `canvas`（2 倍像素，先填 `opaqueBackdrop` 换算后的卡片色）→ `toBlob("image/png")` → base64 → `clipboard.writeImage`。

## 9. 截图、长图、录屏（`Sources/DevBarCapture/`）

### 9.1 抽取原则

- 耦合替换表（方案 §7.2 已核实）：

| Vorssaint 依赖 | DevBar 替换 |
|---|---|
| `DefaultsKey` / `Settings` / `Preferences` | `CaptureSettings`（保存位置等，由 App 注入） |
| `FeatureStrings` | `Strings`（中文常量） |
| `NotchService`、`ColorSamplerService` | 删除相关分支 |
| `RecorderSupport.Region`、像素对齐 | 抽到 `DevBarCapture/Geometry/CaptureRegion.swift`，截图和录屏共用 |
| `ScreenCaptureSelectionOptions` | 精简为 `SelectionOptions { freeze: Bool, purpose: .screenshot / .scrolling / .recording }` |
| `MediaImageFormat` | 只保留 PNG |

| `Permissions` | `CapturePermissions`（§9.5） |
| `AXIsProcessTrusted` / `AXUIElement` 分支 | 删除（窗口截图已不做） |

- 抽取后 `DevBarCapture` 必须能独立编译，不依赖 `DevBar` 目标。

### 9.2 选区（`SelectionOverlay`）

- 每块屏幕一个全屏透明窗口（`level = .screenSaver`，`ignoresCycle`），显示变暗遮罩和选区框、尺寸标签。
- 普通截图：先对每块屏幕截一张静帧铺在遮罩下（冻结画面）；长图和录屏：**不冻结**，遮罩下是实时画面。
- 选区只能在一块屏幕内（从按下鼠标的屏幕开始，拖出边界时夹在该屏内）。
- Esc 取消；回车或松开鼠标确认（录屏需要再点「开始」）。
- 输出：`CaptureRegion { displayID, rectInPoints, scale }`，坐标统一为该屏幕左上原点的点坐标，像素对齐。

### 9.3 区域截图

- `SCScreenshotManager.captureImage(contentFilter:configuration:)`（或冻结帧直接裁剪）得到 `CGImage`。
- 输出：写 PNG 到保存目录，文件名 `DevBar 截图 2026-11-10 18.42.05.png`（重名时追加 ` (2)`）；同时写入剪贴板（PNG 表示 + 文件 URL）——剪贴板监听会把它记成一条新历史。

### 9.4 长图

- 沿用 Vorssaint 的人滚我拼：选区确定后进入采集，顶部显示小控制条「完成」「取消」和已拼高度；用户自己滚动页面。
- 上限：120 秒、512 帧、6000 万像素，任一达到即自动完成。
- 拼接失败（找不到重叠）：停止追加新帧，保留已拼部分，控制条提示「从这里开始无法对齐，已保留前面的部分」，用户可选「完成」。
- 输出同 §9.3，文件名 `DevBar 长图 ….png`。

### 9.5 权限（`CapturePermissions`）

- 屏幕录制：`CGPreflightScreenCaptureAccess()`；未授权时 `CGRequestScreenCaptureAccess()`；仍未授权 → 截图录屏页显示说明和按钮「打开系统设置」（`x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`）。
- 麦克风：`AVCaptureDevice.authorizationStatus(for: .audio)`；打开麦克风开关时 `requestAccess`；拒绝则开关弹回，显示说明和「打开系统设置」（`…?Privacy_Microphone`）。

### 9.6 录屏

**状态机**放在 `DevBarCore/Recording/RecordingStateMachine.swift`（纯逻辑，可单测）：

```
idle ──start──▶ preparing ──streamStarted──▶ recording ──stop / interrupted / lowDisk / sleep / quit──▶ finishing
preparing ──failed──▶ failed
finishing ──didFinish──▶ completed
finishing ──didFail(fileUsable)──▶ incomplete
finishing ──didFail(!fileUsable)──▶ failed
completed / incomplete / failed ──reset──▶ idle
```

- 非法迁移（如 `recording` 时再 `start`）被忽略并记录。

**实现**（`DevBarCapture/Recording/ScreenRecorder.swift`）：

- `SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)` 取目标屏幕；`SCContentFilter(display:excludingWindows:)` 排除 DevBar 自己的窗口（面板、HUD、控制条）。
- `SCStreamConfiguration`：`sourceRect` = 选区（点坐标）；`width/height` = 选区 × scale（偶数对齐）；`showsCursor = true`；`capturesAudio = 系统声音开关`；`captureMicrophone = 麦克风开关`；`sampleRate = 48000`；`channelCount = 2`；`minimumFrameInterval = 1/60`。
- `SCRecordingOutputConfiguration`：`outputURL` = 保存目录 `DevBar 录屏 2026-11-10 18.42.05.mov`；`outputFileType = .mov`；`videoCodecType = .h264`。
- 顺序：`stream.addRecordingOutput(output)` → `stream.startCapture()`；停止：`stream.stopCapture()`，**等待** `recordingOutputDidFinishRecording` 才进入 `completed`；`recordingOutput(_:didFailWithError:)` 时检查文件是否存在且 `AVURLAsset` 可读时长 > 0，决定 `incomplete` / `failed`。
- 异常（方案 §7.3）：`SCStreamDelegate.stream(_:didStopWithError:)` → `interrupted`；开始前 `volumeAvailableCapacityForImportantUsage < 2GB` → 提示并让用户确认是否继续；录制中每 5 秒检查一次，< 500MB → `lowDisk`；`NSWorkspace.willSleepNotification` → `sleep`；`applicationShouldTerminate` 在 `recording/finishing` 时返回 `.terminateLater`，收尾完成或 5 秒超时后 `reply(toApplicationShouldTerminate: true)`。
- 菜单栏：`recording` 时图标换成 `stop.circle` + `mm:ss` 计时（每秒刷新）；`finishing` 时换成进度图标，不响应「开始」。
- ~~最近录制列表~~（方案第 11 版删除）。录屏完成后在屏幕上方显示提示条「录屏已保存」+「在 Finder 中显示」按钮（`NSWorkspace.activateFileViewerSelecting`），5 秒后淡出；截图、长图完成后提示「已保存并复制」。提示条复用剪贴板 HUD 的样式（§7.6），但可点击。
