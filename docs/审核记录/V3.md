## 审核：V3 剪贴板读取授权实测（R3，Claude「菜单工具」会话实现）

结论：**通过**，已合并进 `main`。

分支 `claude/r3`，提交 `0d4aef3`。审核方：Claude「审核」会话（需求方同意由本会话审核；按分工原本应由 Codex 审，注意这是同一模型的不同会话，独立性弱于跨模型审核）。

### 已核实

1. **接口与头文件一致**：对照本机 Xcode 26.6 SDK 的 `AppKit.framework/Headers/NSPasteboard.h`——`NSPasteboardAccessBehavior` 四个取值 0–3、`NS_SWIFT_NAME(NSPasteboard.AccessBehavior)`、`API_AVAILABLE(macos(15.4))`、`accessBehavior` 属性（第 170 行）、`.default` / `.ask` / `.alwaysDeny` 的注释原文、detect 系列的注释（第 246、320 行）都与记录一致；`AppKit.swiftmodule/arm64e-apple-macos.swiftinterface` 第 1936–1940 行的 `detectedPatterns` / `detectedValues` / `detectedMetadata` 签名一致。
2. **探针不输出内容、不参与构建**：整个文件在 `#if DEVBAR_CLIPBOARD_PROBE` 内；日志只有状态、计数、类型数量、长度、是否读到。在合并副本里跑 `Scripts/check.sh`：退出码 0，Swift 43 项、Web 164 项（探针未参与）。
3. **自己复跑探针**：按记录的命令编译，换一个新的应用标识 `local.devbar.clipboard-probe-review`，运行 `--types --detect`：读到 `alwaysAllow`、类型 6 个、无弹窗、日志里没有任何内容——与记录 §3.1「本机默认未启用」一致。
4. **开发者预览开关已关闭**：`defaults read local.devbar.clipboard-probe EnablePasteboardPrivacyDeveloperPreview` 已不存在，没有残留。
5. **4 点结论站得住**：`.default` 按询问处理有头文件原文支撑；「读内容同步阻塞到点完弹窗」有 2.6–15.3 秒实测；「不允许只管一次」有实测；「读类型不弹窗」有实测。已写回 `docs/实现规格.md` §7.4。

### 小问题（不阻塞）

- 复跑时 `detectedMetadata` 返回错误 `NSCocoaErrorDomain 67587`（剪贴板不是文件时没有元数据），记录里没写；既然结论是不接入 detect 接口，不影响。
- 「公开讨论提到开发者预览会改变菜单的承载方式」这句来源不够明确，属于未核实信息；结论「不在 DevBar 里打开该开关」本身不依赖这句。

### 未能实测项的意见

- **`.alwaysAllow` / `.alwaysDeny` 无法手动设置**：如实说明了。系统没启用这项保护时设置界面不出现，这是系统行为，不是测试缺陷。按 §7.4 结论用单元测试注入假状态覆盖即可。
- **`tccutil reset` 不生效**：原因判断正确（`/tmp` 下的应用没注册到 LaunchServices）。以后真要测，可以把探针放进 `~/Applications` 并用 `lsregister` 注册后再试；目前没有必要。
