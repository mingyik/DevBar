### 必须改

1. **CodeMirror 高亮样式写死，不随 tokens 变化**（Codex 发现，Claude 复现）
   - 位置：`Scripts/gen-tokens.ts` 的 `renderCodeMirror()`，`fontWeight: "600"`、`fontStyle: "italic"`、`tabular-nums` 都写在模板里。
   - 复现：把 `syntax.keyword.weight` 改成 500，生成结果仍是 600。
   - 要求：字重、斜体、等宽数字从 tokens 生成（或引用 `tokens.css` 里对应的 `-weight` / `-style` / `-variant` 变量）；补测试：改 token 后产物随之变化。

2. **Swift 产物的引用角色只看白主题**（Codex 发现，Claude 复现）
   - 位置：`renderSwift()` 对 `ref` 角色只用 `light.ref`，样式属性（字重、斜体、等宽）也只取白主题。
   - 复现：把黑主题 `syntax.string.ref` 改成 `text.primary`，CSS 正确变化，Swift 仍调用 `textSecondary`。
   - 要求：按主题分别解析引用；白黑样式属性不同时也要分别生成（或在生成器里校验两套样式属性必须一致，不一致直接报错——二选一，回报里说明）；补白黑配置不同的测试。

3. **Swift 字面颜色检查漏检很多常见写法**（Codex 发现两种，Claude 补测出另外四种）
   - 位置：`Scripts/check.sh` 的 `swift literal colors` 一段。
   - 复现：以下 6 行放进 `Sources/DevBar/` 全部未被拦截：
     ```swift
     let a = Color( red: 1, green: 0, blue: 0)
     let b = Color(white: 0.5)
     let c = NSColor(white: 0.5, alpha: 1)
     let d = Color(.sRGB, red: 1, green: 0, blue: 0)
     let e = NSColor(srgbRed: 1, green: 0, blue: 0, alpha: 1)
     let f = Color(hue: 0.5, saturation: 1, brightness: 1)
     ```
   - 另外：现在的写法是**整行**排除含 `#expect`、`#available` 等宏的行，同一行里真正的颜色值会被一起放过。
   - 要求：
     - 覆盖 `Color(` / `NSColor(` / `CGColor(` 后跟任意空白、换行，以及 `red:`、`white:`、`hue:`、`srgbRed:`、`displayP3Red:`、`.sRGB`、`.displayP3`、`calibratedRed:`、`calibratedWhite:`、`deviceRed:`、`deviceWhite:` 等构造方式；系统语义色（`.primary`、`NSColor.labelColor` 等）不拦。
     - 十六进制只匹配字符串里的 `#RGB` / `#RRGGBB` / `#RRGGBBAA`，不整行排除宏；改为只去掉宏名本身再匹配。
     - 建议把检查从 `check.sh` 里抽成独立脚本（如 `Scripts/check-swift-colors.ts`，Node 运行），便于测试。
     - **允许标记**：同一行带 `// devbar:allow-color` 注释时不报（Swift 和 Web 两边都支持）。原因：剪贴板要识别文本里的 `#RRGGBB`、`rgb(…)` 来显示色块（规格 §7.7），这类识别代码必须写颜色正则。标记要在测试里覆盖，并在 `AGENTS.md` 红线 3 后补一句用法。
     - 补检查脚本的测试：上面 6 种写法 + 多行构造 + 带宏的同一行 + 允许标记 + 语义色不误报。

4. **JSON 的键没有任何高亮样式**（Claude 发现）
   - 方案 §3.1 规定「JSON 键、代码关键字：字重 600」。但 CodeMirror 的 JSON 键是 `tags.propertyName`，Shiki 的 JSON 键作用域是 `support.type.property-name.json`，两份产物都没有映射，键会显示成普通文字。
   - 要求：`syntax.keyword` 同时映射到 CodeMirror 的 `tags.propertyName`（以及 `tags.definition(tags.propertyName)`），Shiki 的 `support.type.property-name`、`meta.object-literal.key`；补测试检查这两个映射存在。

5. **Mermaid 的线条和边框几乎看不见**（Claude 发现）
   - `lineColor`、`nodeBorder`、`clusterBorder`、`actorBorder` 等取的是 `line.border`（白主题 9%、黑主题 11%），叠色后白主题是 `#DCDCDC`、黑主题是 `#353537`，和图的底色对比度只有约 1.3:1，流程图的连线和节点边框基本看不见。
   - 要求：Mermaid 里**承担结构的线**（`lineColor`、`signalColor`、`nodeBorder`、`clusterBorder`、`actorBorder`、`noteBorderColor`、`taskBorderColor`、`pieStrokeColor`、`tagLabelBorder` 等）改用 `text.tertiary`（60%）；纯装饰的分隔（`gridColor`）可以保持 `line.divider`。数值仍是占位，第 4 期按样张再调。
