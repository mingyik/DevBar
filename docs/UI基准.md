> 2026-11-10 由需求方确定。面板外观以本文为准；与 `docs/实现规格.md` §6.2、§6.3 冲突时以本文为准。
> 对照图：`docs/UI参考/参考-面板质感.png`（玻璃质感）、`docs/UI参考/参考-CodexBar布局.webp`（布局：分隔线代替卡片、左右信息分层）、`docs/UI参考/R2-初版-待改.png`（R2 初版，问题见 §4）。
> **【第 3 版，2026-11-11】** 页面拆成 4 页（剪贴板 / JSON / 二维码 / 文稿；编码并进 JSON 页），整体框架（玻璃、顶栏、分隔线、不套卡片）不变；参考 Frset 官网示意图（`Frset` 的面板色彩全来自桌面壁纸透出，自己只有深灰）调整质感、按钮和各页尺寸，见 §6，与 §2、§3 冲突处以 §6 为准。
> **【第 2 版，2026-11-10】** 需求方改为：**去掉页签栏，不做侧边栏**，一次只显示一页，⌘P 切换；截图录屏不在面板里；布局参考 CodexBar，少用卡片。§1、§3 按此重写。

## 1. 要什么、不要什么

| 要 | 不要 |
|---|---|
| Vorssaint 参考图的**通透玻璃质感**：能隐约透出桌面壁纸的颜色 | 参考图顶部的**小箭头**、**品牌图标** |
| CodexBar 的**分隔线分组**：内容直接铺在玻璃上，段与段之间一条细线 + 留白 | **页签栏、侧边栏**（R2 做的图标页签轨道要删掉） |
| CodexBar 的**左右信息分层**：左边标题 / 内容，右边灰色小字（时间、来源、数量） | 嵌套的**卡片框**（玻璃上再套一层卡片） |
| 页面名字 + 灰色「⌘P」提示，告诉用户怎么切换 | **彩色**：蓝色选中、彩色细条一律不用 |
| 任何标签都不换行 | 面板里的截图录屏页 |

## 2. 面板背景（玻璃）

参考实现：`Reference/Vorssaint/Sources/Vorssaint/UI/Theme.swift` 的 `PanelGlassSurface`、`UI/SharedUI.swift` 的玻璃背景。

| 系统 | 做法 |
|---|---|
| **macOS 26**（唯一支持的系统） | SwiftUI `.glassEffect(.regular, in: RoundedRectangle(cornerRadius: 12, style: .continuous))`，上面只叠一层**很淡**的底色 `panel.glassTint`（白主题约白 24%、黑主题约黑 19%；即参考实现里 `baseFill × 0.35 / × 0.45`），再加 0.7pt 描边。**不再叠满 `panel.base`** |
| 系统开启「降低透明度」 | 不用玻璃，用不透明的 `opaqueBackdrop` + `panel.base` |

- 玻璃的外观（`appearance`）必须跟随 DevBar 的白 / 黑设置，而不是跟随系统，否则手动选白主题时材质仍是深色。
- 顶部高光：保留参考实现 `rimHighlight` 的做法（0.7pt 描边从上到下由亮变暗），不用整块渐变色带。
- 新增设计变量 `panel.glassTint`（白、黑各一），由 `design/tokens.json` 生成，不在代码里写数值。

## 3. 布局

```
┌──────────────────────────────────────────┐
│  剪贴板  ⌘P                      📌 ◐ ⤢  │  ← 顶栏：页面名字（可点，点了切下一页）+ 灰色「⌘P」；右侧 3 个按钮
│  ──────────────────────────────────────  │  ← 0.7pt 分隔线
│  SELECT * FROM users WHERE …       刚刚  │  ← 列表行：左内容，右灰色小字
│  ──────────────────────────────────────  │
│  https://example.com/a?b=1      3 分钟前 │
│  ──────────────────────────────────────  │
│  …                                       │
└──────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 面板尺寸 | 默认 420×560；「工具」「文稿」可放大到 600×700（不变） |
| 面板外边距 | 左右 16pt，顶部 12pt，底部 12pt |
| 顶栏 | 高 32。左：当前页名字（剪贴板 / 工具 / 文稿），15pt 半粗，`text.primary`；名字后 6pt 处一个「⌘P」，11pt，`text.tertiary`。名字本身可点击，点一下切到下一页，悬停时名字下方出现 0.7pt 下划线。右：钉住、白/黑、放大 3 个图标按钮，24×24，图标 13pt，无底色，悬停时出现 `panel.control` 圆角 7 底；钉住时图标用实心版本；放大只在「工具」「文稿」页显示，其他页不占位 |
| 顶栏下分隔线 | 0.7pt，`line.divider`，左右与内容对齐（不顶到面板边） |
| 内容区 | **不套卡片**，直接铺在玻璃上。剪贴板：列表行之间 0.7pt 分隔线；工具 / 文稿：编辑区和预览区直接铺满内容区，只在顶部有分隔线 |
| 列表行（剪贴板） | 行高 52；左：内容预览（13pt，最多两行），右：时间（11pt，`text.tertiary`，右对齐）；来源应用小图标放在时间左边；当前条目整行用 `panel.control` 圆角 7 底 + 左侧 2pt 竖条（文字色），不用整行反色 |
| 次要信息 | 一律 11pt、`text.tertiary`、右对齐；与左侧内容基线对齐 |
| 切换动画 | ⌘P 切页时内容淡入淡出 0.15 秒，顶栏名字同步更新；不做左右滑动 |
| 文字 | 任何位置的标签都不允许换行；放不下时缩短文案，不缩小字号 |
| 代码块、表格、Mermaid 图 | 仍各自放在圆角 10 的浅底块里（`panel.card`），这是内容本身的容器，不算「卡片套卡片」 |

## 4. R2 初版的问题（对照 `R2-初版-待改.png`，历史记录）

1. 页签写了文字，「剪贴板」「截图录屏」换行，四个页签宽度不一。→ 改为只放图标的等宽页签。
2. 背景太闷：旧式材质上叠满 42% 黑，几乎看不到透明感。→ 按 §2 改。
3. 页签栏和内容之间有横线，内容没有卡片分组。→ 按 §3 改。
4. 三个操作按钮有方块底色，和页签抢视觉。→ 移到页面标题行右侧，平时无底色。

## 5. UI 验收方式（每轮都做）

凡是改了界面的轮次，回报里必须附**截图**，审核时逐张对照本文：

- 白、黑两套主题 × 默认 / 放大两种尺寸，共 4 张；
- 再加一张：黑主题放在**彩色壁纸**上（检查玻璃透出的效果）；
- 截图存进 `Screenshots/<轮次>/`，文件名写明主题和尺寸。

截图条件：显示缩放默认、系统未开「降低透明度」与「增强对比度」（另有专门的高对比验收时除外）。

## 6. 【第 3 版】参考 Frset 的调整（2026-11-11）

对照图：Frset 官网 `clipboard_preview.png`、`tool_json.png`、`tool_qr.png`、`search_time.png`、`annotate.png`。只借鉴质感与布局，**颜色一律灰阶**（红线 3）；Frset 的蓝色主按钮、紫色渐变不要。

### 6.1 质感

| 项 | 调整 |
|---|---|
| 玻璃通透度 | Frset 的面板能清楚透出壁纸颜色。`panel.glassTint` 在白、黑主题各降一档（白约 24%→18%，黑约 19%→14%，实际值在彩色壁纸截图上对照后定），描边仍 0.7pt；文字对比度不得低于 0.60（`design/tokens.json` 的检查照旧） |
| 圆角 | 面板圆角 12→16；块内（代码块、结果区、二维码底板）圆角 10；按钮 / 胶囊 8 |
| 内层深色块 | 代码、结果、二维码放在比面板更深一级的**半透明深色块**里（`panel.card`，黑主题更深、白主题更浅），块内边距 12，不描边 |
| 数据字体 | JSON、代码、编码结果、二维码原文一律等宽字体，数字等宽对齐；标签（「原文」「结果」）用系统字体 11pt 灰色 |

### 6.2 按钮

| 位置 | 样式 |
|---|---|
| 顶栏右侧图标（钉住、白/黑、放大） | 24×24，图标 13pt，无底色，悬停 `panel.control` 圆角 8；与 Frset 顶栏图标同大小，不加文字 |
| 页内工具行（顶栏分隔线下，高 32） | 左：**分段开关**「原文 / 预览」（⌘E），两格等宽、选中格用 `panel.control` 底 + `text.primary`、未选中 `text.tertiary`，高 24、圆角 8；右：图标按钮（复制、可再加一个）24×24 |
| 底部操作行（格式化 / 压缩 / 转义 / 反转义；编码 / 解码） | **胶囊按钮**：高 28、左右内边距 12、圆角 8、12pt、图标 12pt + 文字；默认 `panel.control` 底；当前最主要的操作（如 JSON 页的「格式化」）用 `text.primary` 作底、反色文字（白主题黑底白字，黑主题白底黑字），一屏最多一个；按钮之间 8pt；放不下时横向滚动，不换行、不缩小 |
| 按钮可点击感 | 悬停 `panel.control` 加深一档；按下缩 0.97；键盘焦点环用 `text.primary` 1.5pt |
| 复制反馈 | 点复制后图标变成对勾 1 秒，不弹 HUD |

### 6.3 结果块（JSON、编码、二维码、文稿代码块通用）

参考 Frset 的「Code」卡片：

```
┌────────────────────────────────┐
│ 结果                        ⧉  │  ← 标题行：11pt 灰标签，右边复制图标
│ ┌────────────────────────────┐ │
│ │ 1  {                       │ │  ← 内层深色块，等宽
│ │ 2    "name": "DevBar",     │ │
│ └────────────────────────────┘ │
│ 10 行 · 187 字符 · JSON  17:22 │  ← 底部信息行：11pt 灰，右对齐时间只用于剪贴板
│ ────────────────────────────── │
│ 原文                           │  ← 编码页、JSON 页可展开「原文」，灰色等宽小字
│ {"name":"DevBar",…}            │
└────────────────────────────────┘
```

- 底部信息行就是状态栏：行数、字符数、类型；出错时同一行显示红色以外的强调（`text.primary` + 错误位置），不用彩色。
- 「原文」小节只在页内出现「结果」时显示，默认折叠为一行，点标签展开；不新增功能，只是把已有的原文与结果并排的方式（⌘E 仍然是主要切换方式）。
- 代码行号：JSON 页、文稿代码块显示行号（CodeMirror 自带），灰色 11pt。

### 6.4 各页面板尺寸（不再统一 420×560）

| 页 | 默认 | 放大 | 说明 |
|---|---|---|---|
| 剪贴板 | 380×520 | 无 | 列表窄一点，像 Frset 的悬浮面板；10 条放得下 |
| JSON | 480×600 | 640×720 | 要看树和长文本 |
| 编码 | 420×480 | 无 | 输入 + 结果两块 |
| 二维码 | 360×480 | 无 | 二维码正方形居中，底下原文和复制 |
| 文稿 | 480×600 | 640×720 | 预览要宽 |

- 切页时面板尺寸 0.15 秒内平滑变化，**顶部（菜单栏图标下方）位置不动**，只向下、左右伸缩；放大状态按页记住。
- 尺寸受屏幕限制，超出可见区域就收缩到可见区域内（原规则不变）。
- 以上数字是起点，R7 对照截图可以调整，调整值写进回报。

### 6.5 页面切换与按钮

- 顶栏左边的「页名 + ⌘P」不变，仍是唯一的切页入口（加上 ⇧⌘P、页面快捷键）；不加图标页签栏。
- 页内「原文 / 预览」分段开关与 ⌘E 同步；文稿页再加一个「Markdown / Mermaid」小分段（自动判断，手动点了即锁定，锁定时显示一个小锁图标）。
- 编码页顶部「URL / Base64」分段开关，规格同上。
- 5 张验收截图改为：各页白、黑各一张（共 10 张）里选 5 张——剪贴板（黑）、JSON（白，预览）、编码（黑）、二维码（白）、黑主题放在彩色壁纸上的剪贴板；文件名写明页与主题。

### 6.6 【同日补充】不做弹窗：Frset 的气泡结果卡改为页内排版

Frset 的结果是从面板里弹出的**气泡卡片**（带小箭头，盖在面板上）。DevBar **不做**：不弹卡片、不弹气泡、不弹第二个窗口，所有内容都在面板本身里，一页一个纵向布局。参考图：`tool_json.png`、`tool_qr.png`、翻译图、`search_time.png`。

```
┌──────────────────────────────────────┐
│  JSON  ⌘P                    📌 ◐ ⤢  │  ← 顶栏
│  ──────────────────────────────────  │
│ ┌──────────────────────────────────┐ │
│ │ {"status":"success","code":200,  │ │  ← 输入块（panel.card，圆角 14）：
│ │  "message":"Data retrieved…"}  × │ │     文字 13pt 等宽；右上角只有「清空 ×」
│ │ ──────────────────────────────── │ │  ← 块内 0.7pt 细线
│ │ [格式化] [压缩] [转义] [反转义]  │ │  ← 胶囊按钮行在输入块里，贴底（§6.2）
│ └──────────────────────────────────┘ │
│  结果                            ⧉   │  ← 结果块直接排在下面（页内，不是弹出）
│ ┌──────────────────────────────────┐ │
│ │ 1  {                             │ │
│ │ 2    "status": "success",        │ │
│ └──────────────────────────────────┘ │
│  10 行 · 187 字符 · JSON             │
└──────────────────────────────────────┘
```

- **输入块在上、结果块在下**，各占内容区一部分，中间可拖动分隔条调高度；有「原文 / 预览」分段开关时，预览替换结果块里的内容，不另开区域。
- 按钮行放在输入块里（像 Frset 搜索框下面的一排按钮、翻译图里的「Translate ⚙ DeepSeek」那一行），不单独悬浮。
- 编码页：输入块 + 「URL / Base64」分段 + 「编码」「解码」胶囊；结果块在下面；底部信息行。
- 二维码页：输入块在上（输入文本，实时生成），下面是二维码块：白色圆角底板（二维码必须黑字白底，这是例外，不算彩色）居中，下面一行信息「290×290 · 复制」，不弹窗。
- 剪贴板页：列表就是页面本身；选中一条后**在列表下面或替换列表显示详情**（具体交互由 R7 按规格 §7 与方案 §4 实现），不弹气泡预览。
- 文稿页：上面输入块（Markdown / Mermaid 分段），下面预览块，或按「原文 / 预览」整块切换；沿用第 10 版纯 Mermaid 规则。
- 圆角：面板 16～20，输入块 / 结果块 14，按钮 8～10；以截图对照为准，写回 `design/tokens.json`。
- 本节不引入新功能：不加「Source Content」之外的新区域，不加翻译、AI、搜索、系统监测。

### 6.7 【同日补充】滚动条：细、轻、不可交互

需求方截图指出现在的滚动条又粗又亮，还带底轨。改为：

| 项 | 要求 |
|---|---|
| 粗细 | 宽 3pt（原生）/ 3px（Web），圆角全圆；离内容右边缘 2pt |
| 颜色 | 滑块用 `text.primary` 约 22% 透明度（白、黑主题各自按设计变量，走 `design/tokens.json`，新增 `scroll.thumb`，文字对比度检查不适用于它）；**没有底轨** |
| 出现方式 | 只在滚动时淡入，停止 0.8 秒后淡出（0.25 秒）；平时不显示 |
| 不可交互 | 不能点、不能拖、不显示悬停加粗；鼠标移上去没有变化；滚动靠滚轮 / 触控板 / 键盘 |
| 范围 | 剪贴板列表、JSON 树与编辑器、文稿预览、编码 / 二维码页内部所有可滚动区域，统一一套 |

- 原生（SwiftUI / AppKit）：滚动视图用 `.scrollIndicators(.never)` 关掉系统滚动条，自己画一个只读的细指示条覆盖在右侧（`allowsHitTesting(false)`）；或 `NSScroller` 用 overlay 样式并设 `ignoresMouseEvents`，二选一，回报里说明。
- Web（CodeMirror、树、预览）：`::-webkit-scrollbar { width: 0 }` 关掉系统滚动条，再用一个 `pointer-events: none` 的细条覆盖显示，滚动时加 `.scrolling` 类淡入。不得用 `scrollbar-width` 之外的需要联网的库。
- 验收：5 张截图里至少一张是列表滚动中的状态；停止滚动后滑块消失。

### 6.8 【同日补充】剪贴板列表：去掉分隔线，改成圆角行（覆盖 §3 的列表行规格）

> **【最新，覆盖下面一切关于行边框与选中的写法】** 剪贴板行的状态：**平时没有边框、只有淡淡的背景**（`panel.card`）；**选中的一行才出现边框**（1.5pt，`text.primary` 约 60% 透明度，圆角 10），选中时背景同时加深一档（`panel.control`）；悬停（未选中）只加深背景、不出现边框。键盘 ↑↓ 移动选中时边框跟着走。拖拽预览卡片的 1.5pt 描边（§6.13）与选中边框是同一种样式。
> **【R7 后以实际为准】** 需求方看过实物后改为：每条不显示来源、不显示时间，右边只写类型（文本 / 图片 / 文件）；每条用细边框包住，选中项用背景色区分；不画行间分割线、不画左侧竖条；各页标题下也不画分割线，标题与内容之间留 8pt。下面表格里与此冲突的「第二行时间 · 来源」「悬停才出现删除按钮」以本说明为准，R7 已按此实现并通过审核。


需求方看了现在的实现（行与行之间一条条横线，右边一排灰色时间和应用图标）觉得难看。参考 Frset 剪贴板列表：每条是**左图标 + 两行字**，没有分隔线。

| 项 | 要求 |
|---|---|
| 分隔线 | **列表里不画任何分隔线**（§3 里「列表行之间 0.7pt 分隔线」作废；顶栏下面那一条仍保留） |
| 行 | 每条是一个独立的圆角行：圆角 10，行高 56，行与行之间留 4pt 空隙；平时底色 `panel.card`（很淡的半透明块），当前选中 / 悬停用 `panel.control` 加深一档，选中不再画左侧竖条 |
| 左边 | 类型图标：24×24，圆角 6，灰阶；文本 / 链接 / 代码 / 颜色 / 图片 / 文件各一个 SF Symbol（单色，`text.secondary`）；颜色值左边是色块（唯一的彩色例外）；图片左边是缩略图 32×32 圆角 6 |

### 6.12 【同日补充】JSON 页底部：JSON · 转义 · 编码/解码 · 清空（覆盖 §6.11 里 JSON、编码两行）

「编码」页并进 JSON 页，面板共 **4 页**（剪贴板 / JSON / 二维码 / 文稿）。JSON 页底部操作栏：

```
[JSON] [转义] [编码 ▾ URL]            预览  复制  长图  清空
```

- **每个按钮点一下就地处理**（改写编辑区文本，一次 ⌘Z 可撤销），按钮是动作，不是模式：
  - **JSON**：内容是合法 JSON 时点一下**格式化**（2 空格）；已经是格式化好的再点一下**压缩**。不合法时不改内容，按钮不可用，状态栏显示错误位置；jsonrepair 能修时出现「修复」胶囊（用户点了才修）。
  - **转义**：标签随内容变化——普通文本显示「转义」（整段变成 JSON 字符串字面量）；内容本身是被转义过的字符串（带引号的字面量，或带 `\"` 的转义文本）显示「反转义」。
  - **编码 / 解码**：一个按钮，标签随内容变化，**保守判断**：URL 模式里含 `%XX` 序列时显示「解码」，否则「编码」；Base64 模式里内容是合法 Base64 且解出可读文本时显示「解码」，否则「编码」。判断只影响标签，用户看到标签才点；不自动执行。按钮右边一个小分段「URL / Base64」，记住上次选择，默认 URL。
  - **清空**：清空编辑区，可 ⌘Z 撤销，不弹确认。
- 右侧固定四个图标按钮：**预览**（树预览，⌘E 同步；预览状态下按钮变「编辑」）、**复制**（复制编辑区当前内容；预览状态下复制树对应的格式化文本）、**长图**（§预览长图，JSON 页）、**清空**。清空放最右。
- URL 模式点「预览」时，内容区显示拆好的表（协议、主机、路径、查询参数）；Base64 模式没有预览，预览按钮置灰。
- 这些按钮的标签文字由 `Strings.swift` / `strings.ts` 集中管理，标签随内容变化时不换行、不改变按钮宽度（取较长文案占位）。
