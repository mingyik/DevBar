# T2.4 系统终端内图片 Enter 确认粘贴

分支：main。需求方 2026-11-14 报告：缓存图片拖到系统 Terminal 中的 OMP 可以加载，悬浮卡片选择后 Enter 只有文字生效。

## 原因与依据

缓存保存的是原始表示，不会自动变成目标应用可读的格式。此前拖拽会生成现存文件 URL 和路径，而 Enter 的图片分支仅恢复原始图片并发送 ⌘V，系统终端可能没有文本可粘贴。

本机安装的是 OMP 18.20.0。该版本文档说明：在没有 OSC 5522 增强粘贴协议时，单个可读图片路径可通过文本粘贴被加载成图片：
https://raw.githubusercontent.com/can1357/oh-my-pi/v18.20.0/docs/keybindings.md

## 做了什么

- `DirectPasteDecision.swift`：增加图片到终端的适配决策，权限、原目标 PID 和禁止粘贴到自身的检查仍优先执行；非终端图片保持原始表示。
- `ClipboardController.swift`：仅对既有 `TerminalApps.bundleIDs` 中的应用，在图片 Enter 路径复用拖拽的临时文件导出，同时写入图片字节、当前文件 URL 和路径文本。标记为自身写回，不产生新历史；发送前再次确认目标未改变。
- `ClipboardDragFile.swift`：提供图片粘贴表示，复用已有文件生命周期和清理策略，不读取已失效的旧截图路径，不修改历史中的原始图片。
- 没有增加辅助功能调用或模拟其他按键；仍然只发送 ⌘V，不发送回车、不提交 OMP 消息。没有改变终端快捷键让出名单。

## 与规格的差异

需求方本次要求修复终端图片确认行为，因此在已有 Enter 例外内增加图片路径适配。临时路径只能供能够访问本机文件的接收端使用，不代表远程 OMP 会自动获得图片。

## 测试与检查

- `terminalImagePasteUsesAReadableFilePathInsteadOfOnlyImageBytes`：终端图片适配；普通图片和终端文本保留原有决策。
- `terminalImagePasteKeepsAuthorizationAndTargetGuards`：未授权、目标改变和自身进程不会绕过保护。
- `terminalImagePasteKeepsImageAndProvidesReadablePath`：从缓存 PNG 和失效旧 URL 生成可读文件；真实 NSPasteboard 同时保留 PNG、URL 和路径，纯文本 NSTextView 能读出路径。
- 最终完整检查：Swift 142 项、Web 350 项通过；Debug 构建及固定签名校验通过，已启动。
