# T2.4 预选卡片跟随输入焦点

分支：main。需求方 2026-11-13 追加修复，覆盖原先“仅首次查询焦点并固定位置”的定位行为。

## 做了什么

- `ClipboardCard.swift`：卡片显示期间每次异步查询结束后间隔 80ms 复查输入光标位置，替换首次查询和连续切换时取消定位的逻辑；AX 查询仍在后台执行，仅读取几何坐标，不读取文本或触发权限弹窗。
- 同一应用内新焦点有有效光标坐标时移动到它附近；查询失败则清除旧坐标，回退到最近一次点击的位置，再回退屏幕居中。
- 全局鼠标监听只在预选卡片显示期间存在，仅记录点击位置、不拦截点击。自动淡出、Esc、Enter 及授权提示会停止查询并清理监听，旧异步结果不会重新移动已关闭卡片。
- `ClipboardCardTests.swift`：增加已显示卡片跟随光标变化、关闭后不再移动，以及跨应用切换后关闭并释放临时快捷键的回归测试。

## 与规格的差异

需求方要求“焦点改变后跟到新位置”，因此从仅首次定位改为显示期间跟踪。粘贴目标仍受原有约束：仅原应用；跨应用切换时收起卡片。此前已向需求方询问是否需要跨应用跟随并更换粘贴目标，尚未收到回复，故未扩大这一行为。

## 测试与检查

- `clipboardCardFollowsChangedCaretWhileAlreadyVisible`：注入几何查询，验证位置变化与关闭后不再移动。
- `clipboardCardClosesWhenFocusMovesToAnotherApplication`：注入前台进程变化，验证卡片与临时快捷键一同关闭。
- `Scripts/check.sh`：见下方运行结果；`Scripts/build-app.sh debug` 构建本地测试包。

## 验收证据与遗留问题

自动测试使用可控制的进程与坐标源，不代表在真实外部应用中完成了 AX 和全屏切换验收。待需求方验证：同一应用中点击不同输入框、Tab 切换输入焦点、点击不支持 AX 坐标的输入框、跨应用收起，以及完整的 Enter 粘贴和方向键恢复。实际延迟包含目标应用的 AX 响应时间，不能把 80ms 查询间隔当作端到端延迟保证。
