# T1.4 运行时安全验证

- 实测日期：2026-11-10
- 机器：macOS 26.7.2（25G332）
- 被测：`main` 上 T1.4 的 WebView 宿主（合并提交 `9070bec`），在分支 `claude/r6` 上以 **Debug 构建**运行（`isInspectable = true`）
- 实测者：Claude（菜单工具会话）
- 结论：**7 项中 6 项通过，1 项不通过（WebContent 进程崩溃后界面没有换上新 WebView）**

## 1. 自检入口（可重复）

新增 `Sources/DevBar/Debug/WebSelfCheck.swift`，整个文件包在 `#if DEBUG` 里；`AppDelegate.applicationDidFinishLaunching` 末尾加了 3 行 `#if DEBUG` 调用。Release 构建里两者都不存在，不改变任何功能代码。

运行方式：

```bash
Scripts/build-app.sh debug
open -n -W build/DevBar.app --args --devbar-selfcheck /tmp/devbar-selfcheck.json
cat /tmp/devbar-selfcheck.json
```

- 自检会打开面板、切到「工具」页，在真实的面板 WebView（`panel.webHost.webView`）里执行检查，约 5 秒后自动退出。
- 开始前备份 `~/Library/Application Support/DevBar/state/`，结束后恢复，不影响用户已保存的内容；自检只写入自己生成的随机标记文本。
- 结果 JSON 只记录检查项、通过与否、状态值和长度。
- 本次连续运行 3 次，结果完全一致。

## 3. 内容拦截规则的单独验证

在 App 的 WebView 里，外部请求同时会被 CSP 拦下，**分不清是哪一层拦的**。所以单独验证规则本身：

1. 从系统规则库取 App 启动时编译的那份规则（`WKContentRuleListStore.default()` 里标识为 `devbar-block-http` 的规则）——取到了，说明 App 确实编译并存入了这份规则。
2. 在本机 `127.0.0.1` 起一个最小 HTTP 服务，返回一张 1×1 PNG，并计数收到的请求。
3. 用两个**不带 CSP** 的 WebView 加载同一个 `http://127.0.0.1:<端口>/probe.png`：

| WebView | 图片结果 | 服务端收到的请求 |
|---|---|---|
| 不挂规则 | 加载成功 | 1 次 |
| 挂上 `devbar-block-http` | 加载失败 | **0 次**（请求根本没发出去） |

结论：规则本身有效，确实在网络层拦下了 `http(s)` 请求。

**没覆盖到的部分**：App 的 WebView 是否确实挂上了这份规则，`WKUserContentController` 没有公开接口可以读出已挂载的规则列表，只能靠代码审核确认（`WebHost.rebuild()` 中 `configuration.userContentController.add(ruleList)`）。另外 T1.4 审核记录提到的问题仍然存在：规则编译失败时只记日志、照常加载页面（失败开放），此时只剩 CSP 一层。

## 4. 不通过项：WebContent 崩溃后界面仍挂着旧的 WebView

做法：在「工具」写入标记文本并等前端保存（1.6 秒），读取 WebContent 进程号（Debug 下用私有键 `_webProcessIdentifier`），`kill -9` 结束它，然后观察。

| 观察项 | 结果 |
|---|---|
| 崩溃前，面板里挂着的是宿主的 WebView | 是 |
| 宿主是否重建（`generation` 1→2）并重新加载页面 | **是** |
| 新 WebView 里内容是否恢复（标记文本） | **是** |
| 崩溃后，面板里挂着的是新 WebView 吗 | **否** |
| 崩溃后，面板里是否仍挂着旧（已崩溃）的 WebView | **是** |
| 关闭再打开面板后，是否换成新 WebView | **否** |

结论：**宿主层面的重建和内容恢复是好的，但界面没有跟上**。用户看到的是已经崩溃的旧 WebView（空白或停止响应），而且重新开关面板也不能恢复。

可能原因（代码阅读，供修复者参考，未验证）：`PanelView` 用 `WebViewBox(host: webHost).id(webHost.generation)` 挂载 WebView，但 `WebHost` 不是可观察对象（没有 `@Observable`），`generation` 和 `webView` 变化时 SwiftUI 不会重新求值视图，`WebViewBox.updateNSView` 也不会被调用。

建议：由 T1.4 的后续修复处理（不在本次验证范围内修改功能代码），修完后用本自检复测，第 7 项应当通过。
