## 依赖核对

去除了规格列出的 Defaults/本地化/灵动岛/取色/选区音频控件/辅助功能等耦合。还需关注这些原实现隐含的依赖：

- `NSScreen.displayID` 扩展：原型直接读 `NSScreenNumber`。
- `ScreenshotOverlayPanel`、`ScreenshotOverlayView` 和鼠标／键盘事件生命周期：在捕获模块内精简，不依赖应用服务。
- `ScreenshotSupport` 的坐标／clamp 工具：只保留矩形运算。
- `WindowPreviewProvider`、`ScreenshotCapturePolicy` 属于窗口截图分支，全部不带入。

`DevBarCapture` 只 import AppKit/CoreGraphics/ScreenCaptureKit，不依赖 DevBar 应用目标或设计变量。临时遮罩采用系统语义颜色，中文提示局限在原型内；正式接线时改为应用注入主题和文案。小于 2 像素的选区直接拒绝，不沿用参考录制器把小选区扩大到 32 像素的行为。

## 复现方法

在本工作目录运行（输出为临时独立验证程序，不安装，不改 Package.swift）：

```sh
mkdir -p /tmp/DevBarCaptureProbe.app/Contents/MacOS
swiftc -swift-version 6 -parse-as-library -D DEVBAR_CAPTURE_PROBE \
  Sources/DevBarCapture/Geometry/*.swift \
  Sources/DevBarCapture/Prototypes/*.swift \
  Tests/DevBarCaptureTests/CaptureProbeRunner.swift \
  -o /tmp/DevBarCaptureProbe.app/Contents/MacOS/DevBarCaptureProbe
```

在该 `.app/Contents/Info.plist` 配置 `CFBundleExecutable=DevBarCaptureProbe`、`CFBundleIdentifier=local.devbar.capture-probe`、`CFBundlePackageType=APPL`、`LSUIElement=true`、`LSMinimumSystemVersion=15.0`，再 `codesign --force --sign - /tmp/DevBarCaptureProbe.app`。

运行 `.../Contents/MacOS/DevBarCaptureProbe --interactive` 人工拖选；不加参数则取主屏预设 320×240 点区域。`--request-permission` 仅在确需系统授权时使用。普通截图先逐屏取静帧，再显示冻结选区；结果裁剪自该帧。文件存 `/tmp/devbar-v4-<UUID>.png`，不写剪贴板、不保存到仓库、不输出用户内容。60 秒无选择会取消。

## 实测证据

环境：macOS 26.7.2 (25G332)、Apple M4、Swift 6.3.3。唯一在线屏幕 DELL P2723D，4096×2304 像素／2048×1152 点，2×。调用前 `CGPreflightScreenCaptureAccess=true`，未触发权限申请。

| 项目 | 结果 |
|---|---|
| 独立模块编译 | `swift build --target DevBarCapture` 通过 |
| 预设区域取图 | display=3，rect=(100,812,320,240) 点，PNG=640×480 像素 |
| 人工拖选 | 需求方在临时界面拖选；display=3，rect=(1145,600,343,312) 点，PNG=686×624 像素，正常返回且遮罩关闭 |
| 负原点副屏、1×/2×坐标、越界裁剪、无效选区 | 几何单测通过；这些是计算验证，不是多屏实机验证 |
| 多屏实机、不同缩放实机 | **未验证**：当前只有一块在线 2× 屏幕 |
| Esc、回车、超时、热插拔 | 已提供路径，尚未逐项人工验收 |
