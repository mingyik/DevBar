# V3 剪贴板读取授权实测

- 实测日期：2026-11-10
- 实测机器：macOS 26.7.2（25G332），Xcode 26.6 自带 SDK
- 实测者：Claude（菜单工具会话），系统设置与弹窗操作由需求方完成
- 日志只记录事件、授权状态、类型数量和长度，没有输出任何剪贴板内容

## 1. 接口与可用版本（以 SDK 头文件为准）

头文件：`/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/AppKit.framework/Headers/NSPasteboard.h`

### 1.1 授权状态

```objc
typedef NS_ENUM(NSInteger, NSPasteboardAccessBehavior) {
    NSPasteboardAccessBehaviorDefault = 0,
    NSPasteboardAccessBehaviorAsk = 1,
    NSPasteboardAccessBehaviorAlwaysAllow = 2,
    NSPasteboardAccessBehaviorAlwaysDeny = 3
} NS_SWIFT_NAME(NSPasteboard.AccessBehavior) API_AVAILABLE(macos(15.4));

@property (readonly, assign) NSPasteboardAccessBehavior accessBehavior API_AVAILABLE(macos(15.4));
```

头文件注释要点（原文摘录）：

- `Default`：「If an app has never triggered a pasteboard access alert, its General pasteboard will report `.default` behavior. Such an app is not shown in the corresponding System Settings pane.」「Once programmatic pasteboard access triggers the first pasteboard access alert, the state automatically changes to `.ask`.」
- `Ask` / `AlwaysDeny`：「access that is both user originated and paste related will always be allowed, and will not result in a notification.」
- Swift 名称：`NSPasteboard.AccessBehavior`，取值 `.default`、`.ask`、`.alwaysAllow`、`.alwaysDeny`。

### 1.2 不读内容的检测接口

头文件中 ObjC 名为 `detectPatternsForPatterns:completionHandler:`、`detectValuesForPatterns:completionHandler:`、`detectMetadataForTypes:completionHandler:`，均为 `NS_REFINED_FOR_SWIFT API_AVAILABLE(macos(15.4))`。注释：「doesn't allow the app to access the item's contents. As a result, the system doesn't notify the person using the app」。

Swift 侧（`AppKit.swiftmodule/arm64e-apple-macos.swiftinterface`）：

```swift
func detectedPatterns(for: Set<PartialKeyPath<NSPasteboard.DetectedValues>>) async throws -> Set<PartialKeyPath<...>>
func detectedValues(for: Set<PartialKeyPath<NSPasteboard.DetectedValues>>) async throws -> NSPasteboard.DetectedValues
func detectedMetadata(for: Set<PartialKeyPath<NSPasteboard.DetectedMetadata>>) async throws -> NSPasteboard.DetectedMetadata
```

可检测的模式：`probableWebURL`、`probableWebSearch`、`number`、`links`、`phoneNumbers`、`emailAddresses`、`postalAddresses`、`calendarEvents`、`shipmentTrackingNumbers`、`flightNumbers`、`moneyAmounts`；元数据只有 `contentType`（仅文件 URL）。

**DevBar 最低系统是 15.0，以上接口全部要 `if #available(macOS 15.4, *)` 包裹。**

## 2. 探针

- 源码：`Tests/DevBarCoreTests/ClipboardAccessProbe.swift`，只在 `-D DEVBAR_CLIPBOARD_PROBE` 时编译，不参与 app 与 `swift test`。
- 构建为独立 app `/tmp/DevBarClipboardProbe.app`（bundle id `local.devbar.clipboard-probe`，ad-hoc 签名），用 `open -n -W` 启动，保证系统把它当作独立应用而不是终端的子进程。
- 构建命令：

```bash
A=/tmp/DevBarClipboardProbe.app; mkdir -p $A/Contents/MacOS
swiftc -swift-version 6 -parse-as-library -D DEVBAR_CLIPBOARD_PROBE -target arm64-apple-macos15.0 \
  Tests/DevBarCoreTests/ClipboardAccessProbe.swift -o $A/Contents/MacOS/DevBarClipboardProbe
# Info.plist：CFBundleExecutable=DevBarClipboardProbe、CFBundleIdentifier=local.devbar.clipboard-probe、
# CFBundlePackageType=APPL、LSUIElement=true、LSMinimumSystemVersion=15.0
codesign --force --sign - $A
```

- 参数：`--types` 读类型列表；`--detect` 调检测接口；`--read` 读字符串；`--monitor 秒数` 每 0.5 秒轮询 `changeCount`，按方案 §4.4 只在「允许」时读内容，加 `--read-anyway` 则每次变化都读（只用于观察系统反应）。

## 3. 实测结果

### 3.1 默认情况：本机根本没有启用剪贴板隐私

| 步骤 | 结果 |
|---|---|
| 全新 bundle id 首次运行，读 `accessBehavior` | **`alwaysAllow`**（头文件说应为 `default`） |
| 读 `types`、调检测、读字符串 | 全部成功，无弹窗，读字符串 0ms |
| 系统设置 →「隐私与安全性」 | **没有任何与「粘贴」相关的分类**（需求方确认） |

结论：在 macOS 26.7.2 上，这项隐私保护**默认关闭**，所有应用都按「始终允许」处理。公开报道与 Apple 开发者论坛也说明目前要用开发者预览开关才会生效：

```bash
defaults write <bundle id> EnablePasteboardPrivacyDeveloperPreview -bool yes
```

### 3.2 只对探针打开开发者预览后

| 步骤 | 授权状态 | 结果 |
|---|---|---|
| 打开开关后首次运行，只读 `accessBehavior` 与 `changeCount` | `default` | 无弹窗 |
| 读 `types` | `default` | 成功（6 个类型），无弹窗 |
| 调检测接口 | `default` | 成功，无弹窗 |
| 读字符串 | `default` → **`ask`** | **弹窗 1 次**（「是否允许粘贴来自其他 App 的内容」类似文案），需求方点「允许」；调用**阻塞 2.6 秒**直到点完，读到内容；之后状态变成 `ask` |
| 轮询 25 秒，只看 `changeCount`、不读内容；期间需求方复制两次 | `ask` | 检测到 4 次计数变化，**无弹窗** |
| 轮询 25 秒，每次变化都读；期间需求方复制两次 | `ask` | **弹窗 1 次**，点「允许」，调用**阻塞 15.3 秒**；阻塞期间的第二次复制没有被单独处理 |
| 读字符串，需求方点「不允许」 | `ask` | 调用阻塞 6.3 秒后返回 **`nil`**；状态仍为 `ask`；随后读 `types` 仍成功 |
| 关掉开发者预览开关 | `alwaysAllow` | 恢复为始终允许 |

未能实测：

- **`alwaysAllow` / `alwaysDeny` 的手动设置**：本机系统设置里没有对应界面，无法切换；弹窗里的「允许 / 不允许」都只管一次，状态一直是 `ask`。
- **`tccutil reset Pasteboard <bundle id>`**：对放在 `/tmp` 的探针报「No such bundle identifier」（未注册到 LaunchServices），未能验证重置。

## 4. 对规格 §7.4 / 方案 §4.4 的结论

**整体够用，需要补 4 点：**

1. **`.default` 按「询问」处理，不读内容。** 头文件写明第一次读内容就会弹窗；规格只说「拒绝 / 询问 / 默认」不读，这一点已覆盖，实现时注意 `.default` 不能当成「允许」。15.4 以下（以及本机这种未启用的情况）按「允许」处理，与规格一致。
2. **读内容会同步阻塞，直到用户点了弹窗（实测 2.6–15.3 秒）。** 因此：
   - 后台监听在非「允许」状态下**绝不读内容**（规格已如此）；
   - 用户主动触发的读取（剪贴板页「有新内容，点击记录」、⌥⌘J「打开工具并带入剪贴板」）**不能在主线程上同步读**，要放到后台任务里，界面显示「等待系统授权…」，返回 `nil` 时提示「未获准读取剪贴板」，不重试。
3. **「不允许」只管一次，状态仍是 `ask`。** 所以「拒绝」分支在当前系统上几乎不会出现；不能依赖它来判断用户拒绝过，用户点「不允许」后由调用结果（`nil`）决定提示，不要把它记成永久拒绝。
4. **不读内容的操作都不弹窗**：`changeCount`、`accessBehavior`、`types`、检测接口在 `default` / `ask` 下都不触发提示。所以 §7.3 第 3 步「先看类型里有没有 `ConcealedType` 等隐私标记」可以放在授权判断**之前**，不读内容就能过滤密码类条目。检测接口对 DevBar 用处不大（只有 URL、数字等少数模式），**不需要接入**。

另外两点提醒：

- **不要在 DevBar 里打开开发者预览开关**。公开讨论提到它会改变菜单的承载方式，影响菜单图标，且这项保护目前对用户本来就没有生效。
- 由于本机默认不启用，第 2、3 点的代码路径在日常使用中几乎走不到，**用单元测试（注入假的 `PasteboardReading`）覆盖即可**，不必为此做额外的手工验收。
