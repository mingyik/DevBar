## 2. 缺陷：⌘V / ⌘C / ⌘X 不可用

**原因（已在代码中确认）**：DevBar 没有设置应用主菜单，`Sources/DevBar` 中没有任何 `mainMenu` / 「编辑」菜单。macOS 上 ⌘V、⌘C、⌘X 是通过「编辑」菜单中「粘贴 / 拷贝 / 剪切」菜单项的快捷键，向第一响应者发送 `paste:` / `copy:` / `cut:` 来生效的；没有这些菜单项，按键就没有去处。

⌘Z、⌘A 能用，是因为 CodeMirror 的键位表（`defaultKeymap`、`historyKeymap`）在网页里直接处理了这两个按键，不经过菜单；而粘贴、复制、剪切需要系统剪贴板，CodeMirror 依赖浏览器原生的剪贴板命令，不自己拦截按键。右键菜单「粘贴」可用，进一步说明问题只在快捷键这一层。

**修复建议（供实现者选择，本次未改代码，均需修复后复测）**：

| 方案 | 做法 | 说明 |
|---|---|---|
| A. 在面板里转发 | 在 `DevBarPanel.performKeyEquivalent` 中识别 ⌘V / ⌘C / ⌘X（以及 ⌘⇧Z 重做），调用 `NSApp.sendAction(#selector(NSText.paste(_:)), to: nil, from: self)` 等发给第一响应者（WKWebView） | 只影响面板内，和「面板不激活应用」的设计不冲突；**推荐** |
| B. 加隐藏的主菜单 | 启动时设置 `NSApp.mainMenu`，包含「编辑」子菜单（撤销、重做、剪切、拷贝、粘贴、全选） | 菜单栏应用的常见做法；但面板不激活 DevBar，系统菜单栏一直属于前台应用，需实测快捷键是否仍会走到 DevBar 自己的主菜单 |

两种方案修复后，都要复测本表第 3–8 项，以及「前台为其他应用时」⌘V 粘贴到的是 DevBar 面板而不是前台应用。

## 3. 关于「改用 .titled 或临时激活应用」

规格 V1 要求在有问题时对比「改用 `.titled` 隐藏标题栏」与「临时激活应用（`NSApp.activate`）」。本次输入法、焦点、全屏都正常，唯一的问题（快捷键）与面板类型无关、是缺少编辑菜单造成的，**不需要改面板类型，也不需要激活应用**。激活应用反而会让前台应用失去焦点，违背「不打断」的设计。
