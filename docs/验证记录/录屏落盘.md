# V5 录屏落盘原型（R1 / Codex）

日期：2026-11-10。工作目录 `~/Desktop/DevBar-codex`，分支 `codex/r1`。

## 范围与实现

`Sources/DevBarCapture/Prototypes/RecordingOutputPrototype.swift` 为新写的最小原型；使用系统 `SCStream + SCRecordingOutput`，不搬 Reference 的 AVAssetWriter／音频／后期管线，不实现 Claude 负责的产品状态机。全屏、H.264、MOV、60fps 目标，系统声音／麦克风关闭。原型每个实例仅运行一次，避免前次回调污染后次实验。

入口在 `Tests/DevBarCaptureTests/CaptureProbeRunner.swift` 的条件编译分支内。构建方式、临时 app 配置与签名见 `截图抽取.md`。用 `/tmp/DevBarCaptureProbe.app/Contents/MacOS/DevBarCaptureProbe --record` 录制主屏约 10 秒；`--record-interrupt` 最长 60 秒，供人工在系统指示器中停止共享。所有媒体只存 `/tmp/devbar-v5-<UUID>.mov`，日志只有事件名、错误码、长度和文件元数据，不打印屏幕内容。

等待 `recordingOutputDidFinishRecording`／`didFailWithError` 后检查文件。正常停止后终态回调等待最多 10 秒，超时单独报告，不能据 `stopCapture` 返回或文件存在判成功。播放检查为 AVURLAsset 的时长、可播放标记、视频轨道，另用 AVAssetImageGenerator 实际解码首帧（第 2、3 轮及后续重试）。超时或不可播放时验证程序退出码非零。

## 环境及 SDK 依据

macOS 26.7.2 (25G332)、Apple M4、Swift 6.3.3；单台 DELL P2723D，4096×2304 像素／2048×1152 点。程序调用前屏幕采集权限已允许；没有申请麦克风权限。

本地 SDK `ScreenCaptureKit.framework/Headers/SCRecordingOutput.h` 将 SCRecordingOutput 标为 macOS 15.0+，声明配置、delegate 的开始／失败／完成回调；实际 API 使用 `init(configuration:delegate:)`，`stream.addRecordingOutput` 后 `startCapture`。最低 macOS 15 只做 API 可用性编译检查，**没有 macOS 15 实机**。

## 正常录制结果

| 次数 | 回调与文件 | 结果 |
|---|---|---|
| 1 | 10.255 秒，4,468,180 字节，1 视频轨道，AVURLAsset 可播放 | didStart／didFinish 均到达；首帧解码尚未加入该轮 |
| 2 | 10.048333 秒，6,625,425 字节，1 视频轨道，首帧解码成功 | finished=true，failed=false，timeout=false |
| 3 | 10.033333 秒，5,026,385 字节，1 视频轨道，首帧解码成功 | finished=true，failed=false，timeout=false |

三轮顺序均为：

```text
startCapture_requested
 didStartRecording
startCapture_returned
stopCapture_requested
stopCapture_returned
 didFinishRecording
```

结论：本机已测正常路径可以直接落 `.mov`，且完成回调晚于 stopCapture 返回，因此必须保留「正在结束」并等待终态。有限次数成功不能证明所有系统／中断场景可靠。

临时媒体：第一轮 `/tmp/devbar-v5-181E38CA-62F8-42A7-B328-D9C482E95972.mov`，第二轮 `/tmp/devbar-v5-01BDF023-601B-4A12-8858-798732B1C09C.mov`，第三轮 `/tmp/devbar-v5-FE145939-31CC-4E70-9E36-BD8F7C13B1A3.mov`。临时文件会被清理，不提交媒体。

## 系统中断与限制

系统中断验收**未完成**。需求方同意配合点击系统停止，但找不到测试程序的停止入口；随后提供的系统提示截图仅显示 ChatGPT，不能确认是验证程序的停止入口。未操作该入口，以免停止其他会话。

两轮等待人工停止的实验均自动跑满，没有收到 `streamInterrupted`：

| 等待时长 | 实际文件 | 结果 |
|---|---|---|
| 30 秒 | 30.02 秒、10,980,918 字节 | finished=true，failed=false，timeout=false，首帧可解码 |
| 60 秒 | 60.04 秒、36,354,965 字节 | finished=true，failed=false，timeout=false，首帧可解码 |

两轮仍是上述正常停止回调顺序，不能记作中断成功，也不能推断中断时文件可用性。没有物理拔掉唯一显示器，也没有用程序主动 stopCapture 冒充系统停止。后续需在可操作系统停止入口的环境，或备有替代显示器的环境补测。

重试文件：`/tmp/devbar-v5-A5341164-CDF6-481C-BEA1-C159551EB32A.mov`、`/tmp/devbar-v5-BC9813F2-0676-4BF0-BC12-2114F68AD440.mov`。

尚未验证：混合缩放多屏、物理拔屏、macOS 15、系统声音／麦克风四组合、低磁盘／休眠／退出收尾。这些不是本次正常落盘成功的推论；后四项产品实现与验收归第 6 期。

## 已知问题与后续建议

- 本机正常路径未出现空文件、缺视频轨道或完成回调超时；系统中断行为尚未验证，不能写成「没有已知问题」。
- 原型使用系统语义／命令行提示，不向正式 DevBar UI 接线；不添加 Package 或应用入口。
- 初步建议保留 SCRecordingOutput 路线。若目标系统实测终态回调缺失，正式实现需要有界超时和文件可用性检查，不能提前标为完成。
