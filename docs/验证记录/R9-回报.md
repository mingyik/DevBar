# R9 · Codex · codex/r9

## 做了什么

- T3.3：修正转义标签判定；保留用户确认的 URL 编码行为和系统橡皮擦。
- T4.1 / T4.7：文稿使用单一内容区及 CodeMirror 编辑、预览，底部左侧仅一个预览／编辑按钮；按内容检测 Mermaid，导入时锁定模式，清空解除锁定。导入及元数据支持撤销。
- T4.4 / T4.5：Mermaid 使用官方浅色／深色主题，移除灰阶变量。预览图缩放适配并使用浅玻璃底；单图常驻系统复制图标。仅针对浅色 Journey、深色 C4 与 Sankey 的文字可读性做局部修正，显式作者颜色保留。普通链接不跳转，⌘ 点击 http(s) 交宿主处理，外图占位。
- T4.6：整页预览长图采用离屏 WKWebView 分块快照，复制并保存；文稿固定 A4 宽 794 CSS px、2 倍输出，按内容延长、不分页。超过单边 16384 px 或 6400 万像素拒绝生成。编辑态截全图先进入预览。
- T3.10：文稿拖入桥接，保留 Mermaid 原始 UTF-8 字节及换行，导入替换可撤销。
- T3.9：新增真实 WKWebView 验证入口、样张、截图与测量记录。

## 与规格的差异和未通过项

- 需求方后续决定优先：彩色主题、图表浅玻璃底、底部仅一个预览／编辑按钮，以及 A4 宽长图；这些覆盖旧的灰阶、图表不透明及按面板宽截图描述。导出 PNG 背景仍不透明。
- 常驻内存目标 <250 MB 尚未达到或证明：在 M4／16 GB 上依次使用 23 个图表、10 种代码、2 MB JSON 树和二维码，静置 5 秒后，单个 WebContent 的 macOS footprint 为 304 MB；按新进程归属统计 RSS 合计约 706 MB（含共享页，不能与物理占用直接相加）。这不是规定的 M1／8 GB 机器，需进一步定位优化和复测；不得判为性能验收通过。
- 最终四组 23 图样张已生成；最终生成的每张图在两种尺寸逐张人工复核尚未完整记录，留待审核。原有对比中发现的 Journey、C4、Sankey 文字问题已局部修正。

- WKWebView 实际粘贴、格式化、压缩、转义、反转义、树预览、复制和撤销，19 位及 20 位整数、1.0、1e10、-0、0.1000 均保留原样；剪贴板实际结果和步骤见 `R9-WK实测.json`。导入撤销、文件名提示恢复及原始换行保真通过。
- 图片导出和复制在 WKWebView 真实桥接执行：长图有末尾内容，超限拒绝生成；单图 PNG 已写系统剪贴板。A4 深色长图尺寸 1588×8092，见 `Screenshots/R9/文稿-深色-A4宽-混合长图.png`。
- 图表浅／深色、默认／放大四组见 `Screenshots/R9/Mermaid-23-*.png`；故意错误的图单独显示错误，后续图仍可显示。截图亦包含文稿、纯 Mermaid、错误卡片和 JSON 链路。
- 性能机器 Apple M4、16 GB、macOS 26.7.2。生产 Web 资源，Swift 优化构建加 DEBUG 测试入口，真实 WKWebView；2 MB JSON 格式化五次 199/208/291/257/247 ms，中位 247 ms；10 MB 五次 911/823/812/830/786 ms，中位 823 ms；2 MB 树首次 157 ms，随后 6/6/4/4 ms。1000 行五张图五次冷进程完整呈现中位 130 ms，首段中位 8 ms。数据为本机参考，不代表 M1 验收。
- 取消验证用真实 Worker，但测试人为延迟响应以确保取消按钮可见；取消后文本不变。未将该测试称为实际慢设备手动验收。
