# T2.4 直接粘贴授权提示兜底

分支：main。需求方 2026-11-13 追加：Enter 粘贴时优先使用系统提示，系统没有提示或用户拒绝后，用 DevBar 自己的授权提示提供设置入口。

## 做了什么

- `ClipboardController.swift`：未授权的 Enter 路径不再只显示“已复制”悬浮卡，改为调用独立授权提示协调器。
- `DirectPasteAuthorizationPrompt.swift`：第一次调用系统 AX 授权提示，保留原有只请求一次的偏好键。首次请求给系统两秒出现窗口的时间，系统提示正在显示时等待其关闭；已经请求过且仍未授权时直接使用 DevBar 提示。系统设置在前台时不抢占操作。
- DevBar 提示包含“打开系统设置”和“暂不授权”；重复按 Enter 不会堆叠提示。取消时若焦点仍在 DevBar，返回提示前的应用；授权后不自动补发粘贴，需用户重新确认。
- `Strings.swift`：增加标题、说明和取消按钮的中文文案。

## 与规格的差异

需求方本次明确要求可操作的授权弹层，因此这一路径允许独立 NSAlert。普通预选卡片和其他面板仍保留原流程。没有新增依赖，也没有重置或修改系统权限数据库。

## 系统接口限制

Apple 明确说明 `AXIsProcessTrustedWithOptions` 的提示异步出现，返回值只表示当前授权状态，没有展示或拒绝回调：
https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions

因此协调器通过公开 NSRunningApplication 和 CGWindowList 窗口元数据，观察本机辅助功能授权代理 `com.apple.accessibility.universalAccessAuthWarn` 的可见窗口。只检查 PID、可见性和矩形，不读取窗口标题、截图或其他应用的 UI 内容。这个代理标识由本机系统包核实，但不是 Apple 承诺稳定的授权回调；若系统版本更改代理，或系统提示延迟超过两秒出现，仍可能需要调整检测。不能把状态机测试视为真实系统弹窗的端到端验收。

## 测试与检查

新增四项测试覆盖：系统弹窗存在时等待、关闭且未授权时兜底、未弹系统提示时超时兜底、此前已请求过仍可打开设置、系统设置操作中不打断，以及授权成功后结束提示。

- `directPasteAuthorizationWaitsForSystemPromptInsteadOfOverlayingIt`
- `directPasteAuthorizationFallsBackWhenSystemPromptDoesNotAppear`
- `directPasteAuthorizationAlreadyRequestedOffersSettingsAgain`
- `directPasteAuthorizationDoesNotInterruptSystemSettingsOrGrantedAccess`

## 验收与遗留

需求方已反馈“已经授权，直接粘贴成功”。实际首次系统弹窗、拒绝和设置按钮跳转仍未手工验证；没有重置用户 TCC 权限进行测试。新 Debug 包已构建，供本机验证。
